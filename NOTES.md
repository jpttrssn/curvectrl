# NOTES — thumbnail listing, RAW rendering & GPU exposure (working state)

Reference for continuing work on Page 1 thumbnails and the detail view.

## File layout

- `src/app.rs` — UI (tiles, detail crossfade, editing panel), async decode pump, all RAW/image helpers (mono reconstruction, base measurement, resize/unsharp, orient).
- `src/exposure_shader.rs` — `ExposureProgram` implementing `iced::widget::shader::{Program, Primitive, Pipeline}` for the detail view.
- `src/shader/exposure.wgsl` — fullscreen-triangle WGSL that samples a linear mono `R16Float` texture, multiplies by `2^EV`, and sRGB-encodes.
- `src/film.rs` — density-space mono inversion + base measurement (`MonoStock`, `ACTIVE_STOCK` = Ilford HP5+).

## Current behavior

- Page 1 lists every regular file in `$HOME/Pictures/exposure` as tiles in a responsive grid, sorted by name. Scanned once at startup.
- Columns adapt to window width; cells never exceed `THUMB_SIZE` px wide and stay square (`Grid::fluid` + `Sizing::AspectRatio(1.0)`).
- Each tile: image area (fills its square cell, `ContentFit::Contain`) + file name below. `image-loading-symbolic` / `image-missing-symbolic` icons for pending/failed.
- Thumbs are rendered as inverted positives via the film pipeline: per-channel level normalize → crop masked borders → mono reconstruction (bayer `flatten_bayer`; cpp≥3 → `luma()` linear Rec.709 collapse) → `measure_base` (p95 = black point anchored on clear film) → `film::invert_gray` (density-space B&W inversion, hardcoded stock) → linear-light area-average downscale to `THUMB_SIZE` → gentle unsharp mask (`UNSHARP_AMOUNT`=0.4, [1,2,1]² blur, linear light before sRGB) → sRGB transfer curve → u8 quantize as `[v,v,v,255]` → `orient` → `Handle::from_rgba`.
- `src/film.rs`: `MonoStock { name, base, d_max, gamma }`; `ACTIVE_STOCK` = Ilford HP5+ (`base=0.82`, `d_max=2.4`, `gamma=0.7` — pending visual tuning). Inversion (shared `positive()` helper): density `log10(base/v)` → normalized position `clamp(density/d_max, 0..1)` → tone curve `position^gamma`. Clear film prints black, the d_max limit prints white. `MIN_PLAUSIBLE_BASE` (0.1) guards against images with no measurable margins.
- Thumbs decode progressively, one at a time, in file order.
- **Detail view**: double-clicking a tile's image replaces the grid with a detail view for that frame (`Length::Fill`, `ContentFit::Contain`, file name caption); Escape returns to the grid. While the GPU decode lands, the cached 384 px thumbnail is shown; once the shader is ready, the thumbnail fades OUT 1→0 over `FADE_SPEED = 5.0` (driven by a `time::every` animation subscription) so the GPU mono texture takes over without a flicker. Earlier approach (`hi_res fading IN over thumbnail`) was flipped because the GPU render is bottom-to-top in `Stack` and the shader is the final layer. Escape closes the view and drops all detail buffers. Only ONE hi-res decode is in flight; selecting another file queues behind the running one (stale results discarded by name).
- **GPU exposure**: detail view runs through an `iced::widget::shader::Shader` that uploads the linear mono `Vec<f32>` once as an `R16Float` texture at decode time (single channel, f32→half converted in `Primitive::prepare` via `mono_to_half_bytes`; half-float is essential because `R32Float` is **not filterable** on WebGPU/wgpu 28 and would fail the `Float { filterable: true }` bind group validation). The WGSL shader applies `2^EV` in linear light and sRGB-encodes per fragment. `ExposureChanged(f32)` writes the new EV into a uniform via `shader.set_exposure(ev)` — zero CPU work, zero per-frame `Handle` allocation, no debounce (uniform writes are ~sub-millisecond). The math is bit-identical to the previous CPU sRGB-LUT path; the slider just moves a number now.
- **Editing panel**: when a detail view is active, an inline panel appears to the right of the image in a `row` layout (no context drawer, no toggle button). Title, exposure label, exposure slider (−3.00 to +3.00 EV, step 0.01), and the formatted value `{:+.2} EV`. While the GPU shader is loading, the panel shows only the title (the cached thumbnail is visible in the image area). Reset to 0.0 on selection change and app start.

## Architecture (model in `src/app.rs`, GPU in `src/exposure_shader.rs`)

- State: `tiles: Vec<Tile>`; `Tile { name: String, thumb: Thumb }`; `Thumb::{Loading, Ready(Handle), Failed}`. Detail state: `selected: Option<String>`, `detail_shader: Option<ExposureProgram>` (set after one decode, dropped on close/reselect), `detail_inflight: Option<String>` (name handed to the single permitted background decode), `detail_thumb_opacity: f32` (1.0 → 0.0 thumb crossfade), `detail_last_frame: Option<Instant>` (framerate-independent fade timing), `detail_thumb: Option<Handle>` (thumbnail kept visible under the fading hi-res), `exposure_ev: f32`. Helper methods: `clear_detail()` resets all detail buffers; `handle_detail_ready()` applies a completed decode.
- Messages: `FilesLoaded(Vec<String>)` builds tiles then starts chain; `ThumbReady(String, Result<Handle, ()>)` stores result and chains next; `ThumbnailActivated(String)` sets/clears selection and pumps the detail decoder; `DetailReady(String, Result<(Vec<f32>, u32, u32), ()>)` applies only when `detail_result_is_current(selected, inflight, finished)` — caches the thumbnail for crossfade, builds the `ExposureProgram`, sets `detail_thumb_opacity = 1.0`, then pumps; `DetailFadeTick` advances the thumbnail crossfade; `ExposureChanged(f32)` writes into the shader uniform directly (no debounce, no echo message); `DetailClosed` (Escape) clears selection + all buffers + resets exposure.
- Decode chain: `decode_next()` picks first `Loading` tile → one `tokio::task::spawn_blocking` per file (`decode_thumbnail`). Strictly sequential, so only one full-res RAW buffer is alive at a time.
- Detail pump: `decode_detail_next()` spawns only when no decode is in flight, something is selected, and its shader isn't ready yet. A superseded decode's arrival frees the slot via the stale guard and re-pumps; failures do NOT auto-retry (re-selecting the file retries on demand).
- Thumbnail pipeline (`convert_thumbnail(image, max_size)`): `rawloader::decode_file` → `normalize_samples` → `crop_samples` → mono reconstruction (`flatten_bayer` for bayer; `luma()` for cpp≥3) → `film::measure_base` + `film::invert_gray` → `resize_area` (linear light, capped at caller's `max_size`) → `unsharp_mask` (linear light) → `srgb_encode` → u8 quantize as `[v,v,v,255]` → `orient` → `Handle::from_rgba`. (Detail path is a *near-duplicate*: same linear pipeline, then `orient_mono`, returning the oriented `Vec<f32>` directly to the GPU.)
- Detail pipeline (`decode_raw_detail`): same as the thumbnail pipeline through `unsharp_mask` on `Vec<f32>` mono, then `orient_mono` (per-element float mirror of `orient`) and `Ok((mono, width, height))`. No CPU-side sRGB encoding, no RGBA packing, no `Handle::from_rgba`. The GPU shader does sRGB encoding per fragment.
- **GPU pipeline** (`Pipeline::new` in `src/exposure_shader.rs`): one-time creation of `ShaderModule` from `include_str!("shader/exposure.wgsl")`, `BindGroupLayout` (texture, sampler, uniform buffer), `PipelineLayout`, `RenderPipeline` (fullscreen triangle, target format `Bgra8Unorm` to match iced's framebuffer on this libcosmic configuration), `Buffer` for the `Uniforms` struct, and a `Sampler` (linear + ClampToEdge). The texture + bind group are created lazily in `Primitive::prepare` on the first frame because they need the mono data. Subsequent frames: only the uniform buffer is updated via `queue.write_buffer`. The WGSL `fs_main` already applies `linear_to_srgb` per fragment, so the target is `Unorm` (linear) rather than `UnormSrgb` — picking `UnormSrgb` would double-encode. The `_format` parameter iced passes is ignored; if libcosmic ever switches to an sRGB-aware framebuffer, this would need a paired change (drop `linear_to_srgb` from the shader or no-op it, then swap the target back to `Bgra8UnormSrgb`).
- WGSL uses the canonical 3-vertex fullscreen triangle (`-1,-1 / -1,3 / 3,-1`) with NDC values passed through directly. Earlier pattern `(vec2(1u, 2u) + vi) % vec2(6u) < vec2(3u)` produced only the upper-right half of the viewport (visually a triangle), because under wgpu the render-pass scissor clips to the viewport rect rather than to the original primitive's bounds.
- `Uniforms.exposure` carries `2^EV` (linear-light gain), NOT the raw EV. `Primitive::prepare` computes the gain once per slider change via `f32::exp2`. At EV=0 the gain is exactly 1.0 (identity). Sending raw EV would render black at EV=0 and over-bright at EV≥1 because the shader's `mono_linear * exposure` would multiply by the slider value instead of the matching gain.
- Texture re-upload is keyed by `image_id: u64` so selecting a second image actually rebuilds the GPU texture and bind group. `AppModel.next_image_id` is a `wrapping_add(1)` counter stamped onto `ExposureProgram::image_id` in `handle_detail_ready`; `ExposurePipeline::current_image_id: Option<u64>` remembers the last installed id. Without this, iced reuses the same `ExposurePipeline` across image selections (it caches by `TypeId`) and the previously-uploaded mono data stays bound to the new shader — visible as "second image still shows first".
- Shader widget is wrapped in `cosmic::widget::aspect_ratio::aspect_ratio_container(shader.view(), shader.aspect())` (ratio = `width / height`). Without this, window resize stretches the texture to fill whatever rectangle the layout hands the Shader widget. With it, the bounds are clamped to the source aspect ratio and the shader renders letterbox/pillarbox instead of stretched.
- **Per-frame uniform** (32 bytes, `Uniforms` struct, matches WGSL): `exposure: f32` (= `2^EV`), the fragment-shader-readable viewport + scissor rect expressed in physical pixels so the fullscreen triangle correctly maps texture UVs to the contained image rect. Computed from `viewport.physical_{width,height}()` and `bounds.{x,y,width,height} × viewport.scale_factor()`.
- Constants: `THUMB_SIZE = 384.0` (decode cap + grid cell), `HI_RES_SIZE = 2048.0` (detail decode cap), `FADE_SPEED = 5.0` (thumb-fade-out units/second, ~0.2 s ramp), `TILE_ASPECT = 1.0`, `UNSHARP_AMOUNT = 0.4`, `BASE_SAMPLE_TARGET = 250_000`, `PANEL_WIDTH = 240.0`.
- View: Page 1 builds `cosmic::iced::widget::Grid::with_children(tiles.map(tile_view))` with `.fluid(THUMB_SIZE)` + `.height(grid::Sizing::AspectRatio(TILE_ASPECT))`, wrapped in a scrollable. Tile image areas use `MouseArea::on_double_click(ThumbnailActivated(name))`. When a selection exists, `detail_view()` REPLACES the grid below the header: the preview is an iced `Stack` with the GPU `Shader` as the bottom layer and `detail_thumb` on top with `.opacity(detail_thumb_opacity)` (later children draw over earlier ones; the thumb fades out from 1→0); once the fade completes the thumb is dropped and the shader shows alone. The detail view and editing panel are laid out in a `widget::row::with_capacity(2)`: `[detail_container, editing_panel]`. COSMIC left toggle remains for the About dialog only.

## Known limitations (likely next-step targets)

1. **Color accuracy / stocks**: inversion POC is mono-only with one hardcoded stock (`film::ACTIVE_STOCK`); cast WB is self-calibrated per image from clear-film plateaus, so frames with no measurable margins rely on the `MIN_PLAUSIBLE_BASE` fallback. Natural next steps: stock picker UI, calibrate-base-from-base-only-frame feature (`measure_base` does the math), AsShot-WB prior for margin-less frames, color stocks using `invert_mono`/`measure_base_channels`.
2. **No refresh** of the folder listing after startup.
3. **Memory unbounded** across many decoded thumbs (no LRU/eviction); ~600 KB each. Detail view holds one oriented mono `Vec<f32>` (~16 MB at 2048×2048 f32) + its GPU texture; both are dropped on close/reselect.
4. Decode errors are silent (`Err(())`); non-RAW files are listed and show the missing icon. A failed hi-res detail decode likewise keeps showing the thumbnail — selecting another file and back retries on demand.
5. **Grain/noise/sharpness**: area-average downscale, luminance collapse, full-res bayer flattening, gentle unsharp mask — plus the post-decode bandwidth savings on the GPU side (one linear texture upload vs. a continuously-re-encoded sRGB image). Remaining stackable option — a denoise pass for very underexposed captures. Capture-side: scans exposed with clear film far left in the histogram waste SNR; exposing so the base sits near saturation (~85–95%) keeps several more stops of detail in dense areas.

## Environment gotchas

- `libcosmic` is a plain git dependency on pop-os master; lockfile pins `ef490df5`. The local clone at `../cosmic/libcosmic` is no longer patched in. Upstream includes the old `AspectRatio::layout` off-by-one fix and iced's `Grid` export. The commented `[patch]` template in `Cargo.toml` can restore the clone if needed.
- The `wgpu` feature on libcosmic is required for `iced::widget::shader::Shader`. Without it the `ExposureProgram` won't have a `Pipeline::new` entry point.
- Verify changes with `just check` (clippy pedantic) and `cargo test --locked`. Expect ~130 warnings from compiling libcosmic master from source — ignore those; only warnings pointing into `src/` matter.
- `bytemuck` is the only binding-layer shim (Pod/Zeroable impls on the `Uniforms` struct); `wgpu` itself comes through libcosmic's vendored re-export. `rayon` was previously a direct dep for CPU exposure re-encoding; it stays only as a transitive of `rawloader`.

## Useful API facts (verified against pinned libcosmic/rawloader)

- `cosmic::Task<M>` aliases `iced::Task<cosmic::Action<M>>`; async work: `cosmic::task::future(async { Message::X(...) })`; batch with `Task::batch([...])`.
- `rawloader::{RawImage, RawImageData, Orientation}` are re-exported at crate root (`decoders` module is private).
- `RawImage` fields used here: `width`, `height`, `cpp`, `data`, `wb_coeffs` ([f32;4] RGBE), `blacklevels`/`whitelevels` ([u16;4]), `orientation`, `cfa`.
- `rawloader::CFA` is crate-exported; `CFA::new("RGGB")` builds test patterns; `color_at(row, col)` mods internally (`(row+48)%48`), so any coordinates are safe. Returns 0=R, 1=G, 2=B, 3=fourth-color. `shift(x, y)` re-phases the pattern after cropping by `(left=x, top=y)`.
- `RawImage.crops: [usize;4]` is `[top, right, bottom, left]`. Tested Canon CR2s flag top/left only; their LAST two sensor rows also read elevated (~9k vs ~2k ADU) despite `bottom=0` — if a bottom-edge artifact ever appears, suspect unflagged masked rows.
- Icons: `icon::from_name("...").icon().into()` yields an Element; image handles clone cheaply.
- **iced `widget::shader`** (verified against pinned vendored iced): reach through `cosmic::iced::widget::shader::{Pipeline, Primitive, Program, Shader, Viewport}`. `Shader::new(program).width(Length::Fill).height(Length::Fill)` wraps a `Program` impl. `Program::draw()` produces a `Primitive`; `Pipeline::new()` is called once when iced first sees a new pipeline type; `Primitive::prepare()` runs every frame; `Primitive::render()` runs every frame and uses an `encoder.begin_render_pass(...)` with `LoadOp::Load` (we draw into an already-painted framebuffer). `viewport.physical_{width,height}()` and `bounds.{x,y,width,height} × viewport.scale_factor()` give physical-pixel coordinates for the scissor region.
- **Other iced widget traits** verified for this feature: `MouseArea::new(content).on_double_click(message)` (takes a message value, not a closure); `cosmic::iced::keyboard::listen()` delivers only keyboard events widgets did NOT capture (Status::Ignored) — fine for a global Escape; `Subscription::filter_map` requires NON-CAPTURING closures (`Fn(T) -> Option<A> + Clone`); `cosmic::iced::widget::Stack::with_children([...])` layers children bottom-to-top in push order — used here for thumb-over-shader layering.
- **WGSL shader** (verified with vendored wgpu 28): `vertex_index` builtin provides 0..2; the per-vertex fullscreen-triangle pattern `vec2<f32>((vec2(1u, 2u) + vertex_index) % vec2(6u) < vec2(3u))` is the standard 3-vertex covering-trick; the render pass viewport is set to the primitive's bounds via `pass.set_viewport(...)` so NDC [-1..1] maps to the rect.
