# NOTES — roll library, thumbnail listing, RAW rendering & GPU exposure (working state)

Reference for continuing work on the roll library (rolls ↔ frame grid ↔ detail view navigation), thumbnails, and the GPU detail pipeline.

## File layout

- `src/app.rs` — UI (tiles, detail crossfade, editing panel), async decode pump, all RAW/image helpers (mono reconstruction, base measurement, resize/unsharp, orient).
- `src/exposure_shader.rs` — `ExposureProgram` implementing `iced::widget::shader::{Program, Primitive, Pipeline}` for the detail view.
- `src/edit_manifest.rs` — per-roll edit persistence: `RollManifest`/`EditData`/`ToneEdit` (serde+toml), the `.film-roll.toml` sidecar reader/writer (atomic temp+rename), `reconcile`, unit tests.
- `src/config.rs` — persisted app config (cosmic-config derive, schema v2): the roll list `rolls: Vec<String>` (absolute roll directories).
- `src/shader/exposure.wgsl` — fullscreen-triangle WGSL that samples a linear mono `R16Float` texture, applies the composed tone remap `ratio·p^exp` and `2^EV` gain, sRGB-encodes, and maps fragments through a zoom/pan transform (`view_uv`).
- `src/film.rs` — density-space mono inversion + base measurement (`MonoStock`, `ACTIVE_STOCK` = Ilford HP5+).
- `src/detail_area.rs` — `DetailArea` widget: an iced-`MouseArea` clone that reports cursor positions relative to the widget **center** (needed by the zoom-anchor math), fires `on_release` when the cursor leaves while pressed (iced suppresses release outside bounds), and stays stateless (`tree::State::None`). A11y nodes omitted (the trait default covers it; no direct `iced_accessibility` dep).

## Current behavior

- **Library page**: the configured film rolls (config key `rolls`, a `Vec<String>` of absolute directories) are listed as cover cards in a responsive grid sorted by roll name. A fixed toolbar sits above the grid — "Add roll" (opens the system folder picker, `cosmic::dialog::file_chooser::open::Dialog::open_folder()`) and a search box that filters roll names live. Re-adding a roll re-scans it, so the button doubles as a manual refresh. A **single click** selects a roll (the whole card highlights with an accent border — see the Library page tile bullet — and it becomes the metadata-drawer target); Enter or a **double-click** anywhere on the card drills into its frame grid. Each card shows a full-bleed cover (crop-filled to the card, clipped at its top corners), the title, and a frame-count caption. Roll covers decode through the same thumbnail pipeline at exposure 0 (roll cards are not per-frame editable).
- **Keyboard grid navigation**: the subscription's `keyboard::listen` filter routes Escape, Enter, and the arrow keys (`Nav(MoveDir)`). On the **library** page arrows move the roll selection by the `grid_cols` row size tracked from `on_window_resize` (mirroring `Grid::fluid`'s `ceil((width + spacing)/(max + spacing))`; `grid_cols` seeded to 3 until the first resize), Left/Right step within a row without wrapping, Up/Down jump a full row clamped to the edges, and a selection-less press lands on the first item (`nav_target`, pure + unit-tested); Enter opens the selected roll (`OpenSelected` → `open_roll`). Inside a **roll**, arrows move the frame highlight over the same filtered set (`grid_cols` reused — the grids share `Grid::fluid` math), Enter opens the highlighted frame (`open_frame`); with the **detail view open**, Left/Right page through the frames instead (`paginate`, clamped, no wrap; Up/Down inert), opening the neighbor in place without closing first. `Ctrl+Space` toggles the **Roll info** drawer (`ContextPage::RollInfo`, library only) — the spacebar carries no `Named` variant in this iced fork, so the binding matches the `Character(" ")` payload with a `modifiers.control()` guard. Escape closes the library drawer, then the detail view, then clears a frame highlight, and only then backs out of the roll. Navigation targets the visible set (`filtered_rolls`/`filtered_tiles` share the toolbar query, so arrows move over what's actually on screen).
- **Roll info drawer**: `ContextPage::RollInfo` renders a `context_drawer` pane (same mechanism as editing) listing the selected roll's name (heading), full path, frame count, and cover file name (or `no-cover`), from a `roll_cover_and_count` scan folded into `load_roll` (`Roll::frame_count`). The drawer needs a library selection: both the menu item (`MenuAction::RollInfo`) and the Ctrl+Space toggle no-op without one, it never opens while a roll is open (`active.is_some()` → `None` in `context_drawer()`), and a selection that loses its roll (e.g. on a re-scan in `RollsLoaded`) drops the selection and closes the drawer.
- On entry, an open roll's frame grid lists every regular non-dot file in the roll directory as tiles, sorted by name (dotfiles — including the edit manifest or its temp — never become tiles). The toolbar search now filters frame names. Fresh configs seed one roll, `~/Pictures/exposure`, in memory only — a real config write happens only when a roll is added.
- Columns adapt to window width; cells never exceed `THUMB_SIZE` px wide and stay square (`Grid::fluid` + `Sizing::AspectRatio(1.0)`).
- Each tile: image area (fills its square cell, `ContentFit::Contain`) + file name below. `image-loading-symbolic` / `image-missing-symbolic` icons for pending/failed.
- Thumbs are rendered as inverted positives via the film pipeline: **linear-light phased downscale straight from the sensor samples** (one fused pass — `downsample_thumbnail`: normalize + drop masked borders + per-CFA-class block averages, never materializing a full-res buffer; RGB sources collapse through the Rec.709 luminance of each block's channel means, which is exact because luma is linear) → `measure_base` (p95 = black point anchored on clear film) → `film::invert_gray` (density-space B&W inversion, hardcoded stock) → **`apply_exposure` (`×2^EV`, identical gain to the detail shader so grid and detail agree)** → sRGB transfer curve → u8 quantize as `[v,v,v,255]` → `orient` → `Handle::from_rgba`. Unsharp mask (`UNSHARP_AMOUNT`=0.4, [1,2,1]² blur) runs on the small mono before exposure, as before. Accepted tone swap: per-class bases and the invert anchor are measured at thumbnail scale after the downscale instead of on full-res samples (flatten-before-average), so high-contrast blocks can differ subtly from the detail render.
- `src/film.rs`: `MonoStock { name, base, d_max, gamma }`; `ACTIVE_STOCK` = Ilford HP5+ (`base=0.82`, `d_max=2.4`, `gamma=0.7` — pending visual tuning). Inversion (shared `positive()` helper): density `log10(base/v)` → normalized position `clamp(density/d_max, 0..1)` → tone curve `position^gamma`. Clear film prints black, the d_max limit prints white. `MIN_PLAUSIBLE_BASE` (0.1) guards against images with no measurable margins.
- Thumbs decode progressively, up to `MAX_CONCURRENT_THUMBS` (4) in flight at once on the blocking thread pool, in file order.
- **Detail view**: double-clicking a tile's image overlays a detail view for that frame on an opaque surface that hides the still-mounted thumbnail grid (the grid never leaves the widget tree, so iced preserves its scroll position across open/close — no snapshot/`snap_to` needed). The detail surface is painted with the window background color (`theme.cosmic().background(false).base`) so the letterbox bars show the same backdrop as before; a full-surface `MouseArea` (`Message::Ignore` on press/release/double-click/scroll) swallows pointer input over the caption/bars so nothing reaches the grid behind, while the preview itself is the interactive `DetailArea` (see Zoom & pan below) (`Length::Fill`, `ContentFit::Contain`, file name caption); Escape returns to the grid. While the GPU decode lands, the cached 384 px thumbnail is shown; once the shader is ready, the thumbnail fades OUT 1→0 over `FADE_SPEED = 5.0` (driven by a `time::every` animation subscription) so the GPU mono texture takes over without a flicker. Earlier approach (`hi_res fading IN over thumbnail`) was flipped because the GPU render is bottom-to-top in `Stack` and the shader is the final layer. Escape closes the view and drops all detail buffers. Only ONE hi-res decode is in flight; selecting another file queues behind the running one (stale results discarded by name). Loading is then progressive through that single slot: the overview (2048 edge) first, and a native-cap re-decode after the zoom crosses `NATIVE_ZOOM_THRESHOLD` that replaces the texture in place (same framing, no crossfade — see the Detail pump bullet).
- **GPU exposure**: detail view runs through an `iced::widget::shader::Shader` that uploads the linear mono `Vec<f32>` once as an `R16Float` texture at decode time (single channel, f32→half converted in `Primitive::prepare` via `mono_to_half_bytes`; half-float is essential because `R32Float` is **not filterable** on WebGPU/wgpu 28 and would fail the `Float { filterable: true }` bind group validation). The WGSL shader applies `2^EV` in linear light and sRGB-encodes per fragment. `ExposureChanged(f32)` writes the new EV into a uniform via `shader.set_exposure(ev)` — zero CPU work, zero per-frame `Handle` allocation, no debounce (uniform writes are ~sub-millisecond). The math is bit-identical to the previous CPU sRGB-LUT path; the slider just moves a number now.
- **Editing panel**: when a detail view is active, the editing panel is shown in the COSMIC **context drawer** as a side pane (`core.window.context_is_overlay = false`, so the image shrinks to make room — matching the old inline 240 px panel). A header toggle button (`header_end`, `edit-symbolic`, tooltip "Show editing panel") opens/closes it; the button is disabled until a file is selected and shows the pressed state while the drawer is open. Content: title, exposure slider (−3.00 to +3.00 EV, step 0.01); below that the **persisted** tone controls — Contrast, Highlight rolloff, and Shadows power sliders (all `0.20..=3.00` step 0.05 at 1.0 identity) — and no numeric value readouts (removed along with the per-section "Reset tone" button), then a divider and a **Reset all edits** button that restores every edit to the values the panel was opened with (the stored manifest state, persisted — see the Edit persistence bullet for the reset snapshot). While the GPU shader is loading the panel shows only the title. The drawer width comes from libcosmic's `context_width()` (344–480 px). Escape closes both the detail view and the drawer. (The Black/White output-level sliders from the follow-up were removed: the inversion already auto-anchors black per frame, so the only gestures available produced a fade rather than a fix.)
- **Zoom & pan**: the preview surface is wrapped in `DetailArea`; the wheel zooms (one notch ≈ half a `log2` unit, trackpad up to `MAX_DETAIL_ZOOM = 7.0`, ≈64× contain) and press+drag pans. Zoom is **continuous from the contain fit**: `scale = contain_s · 2^(zoom−1)`, so at `zoom == 1` the view is byte-identical to today's `ContentFit::Contain` and bars recede gradually; the frame fills the shader at `1 + log2(cover/contain)` and keeps overflowing beyond (never clipped to the letterbox band — user's explicit requirement). The pan keeps the image point under the cursor pinned across zoom steps (`zoom_about_anchor`: `off1 = off0 + (1 − 2^(z1−z0))·(cursor − off0)`; the render scale is proportional to `2^(zoom−1)` so the unknown contain width cancels, and `DetailArea` supplies the cursor **center-relative** so the widget center never enters the formula either — iced's plain `MouseArea` gives top-left-relative positions, which would shift every anchor by the unknown widget center). Zooming back out to 1 re-centers (fit view must be centered); zooming out past cover does not snap. Pan is unclamped (bars show while dragging past an edge; a shader-side soft clamp is a possible later step). `on_release` also fires on cursor-leave-while-pressed and on `CursorLeft` so a grab-pan can never stick. Wheel over the caption/bars still zooms (iced delivers the wheel event to the widget under the tree regardless of hover, and iced's own `MouseArea` has no `over` guard on wheel either); the outer blocking `MouseArea`'s `on_scroll(Ignore)` remains as backstop for the grid.
- **Tone model (persisted, orthogonal controls — exposure, contrast, highlight rolloff, shadows)**: the editing drawer carries a live tone preview with **Exposure** (`2^EV` gain — everything moves together) and three **pivoted powers** — **Contrast** `kc` (pivot at the image's measured **mid-gray** `m`: `C(p)=m^(1−kc)·p^kc`), **Highlight rolloff** `kr` (pivot at the measured **white point** `w` ≈ 98th %ile: `R(p)=w^(1−kr)·p^kr`), and **Shadows** `ks` (pivot at the measured **shadow anchor** `s` ≈ 10th %ile: `S(p)=s^(1−ks)·p^ks`). The pivot-at-an-image-anchor framing is the whole point: the previous panel's D-max/gamma were *mathematically* near-duplicates of exposure — at default gamma, D-max `T(p)=(2.4/d)^0.7·p` is literally a pure gain (≈ ±0.9 EV), and gamma's power was anchored at the display black/white, far outside the frame's actual tone band, so it read as brightness too. Three monotone powers still compose **exactly** into one power, so all three sliders fit the same two uniforms: `ratio = s^(1−ks)·w^(ks·(1−kr))·m^(ks·kr·(1−kc))`, `exp = kc·kr·ks` (`curve_remap` in `exposure_shader.rs`) — at defaults `kc=kr=ks=1` the remap is the identity and untouched renders stay byte-identical. (Output-level **Blacks/Whites** endpoints were prototyped and **removed**: the inversion already auto-anchors black per frame via `film::positive` mapping `transmission == base` → exactly 0, so the only slider directions available raised the floor to grey or clipped highlights the rolloff power already shapes — a fade, not a fix.) Anchors are measured once per detail decode with `tone_anchors` (single-pass 4096-bin histogram over the uploaded positive, O(n) — no sort of a 2048² buffer; 10th/50th/98th percentiles, all clamped to ≥ `MIN_ANCHOR`=1e-3 to keep `pow(0, negative)` from NaNing degenerate all-black frames). The tone edits are **persisted** like exposure: `clear_detail()` resets the powers to 1.0 but every open re-sources the stored `(contrast, rolloff, shadows)` from the manifest, and grid thumbnails bake them too. The shared pure helpers `curve_remap` / `apply_curve` (both `pub(crate)` in `exposure_shader.rs`) keep grid and detail agreeing — `convert_thumbnail` measures the same anchors with `tone_anchors` and applies `apply_curve` *before* `apply_exposure`, mirroring the shader's ordering exactly (curve remap → `2^EV` → clamp → sRGB). Caveats accepted: `pow` re-rounds through the f16 texture (double rounding); unsharp edge detail was computed pre-curve and is re-curved rather than re-derived; an intermediate clamp would break composition (the shader applies one final clamp, matching `curve_remap`).
- **Edit persistence**: each image's exposure and tone-curve power edits survive image switches, detail close, and app restarts via a per-roll manifest, `.film-roll.toml` (TOML, `{ version, name?, edits: { <name>: { exposure_ev, curve_contrast, curve_rolloff, curve_shadows } } }`, schema `version = 3`) living in the roll directory (`~/.…/exposure/` for the POC). The manifest file name is deliberately function-based rather than app-based so an **app rename never orphans existing sidecars** (remember also `APP_ID = "dev.mmurphy.Test"` and `CARGO_PKG_REPOSITORY` when renaming; `Config` follows `APP_ID` automatically). Loading: `RollOpened` loads the active roll's manifest once on drill-in and `reconcile()` drops entries whose file is no longer in the scan, so a recycled file name can never reattach stale edits. Writing is RAM-first: `ExposureChanged`/`CurveChanged` mutate `roll.edits` only; flushes happen on slider drag-end (`Slider::on_release(Message::EditSave)`), on `DetailClosed`, and on window close (`on_close_requested → None→Some(EditSave)`); `save_roll_manifest` writes a temp file then renames (atomic). Reads consolidate on `ToneEdit` — a `pub` aggregate of exposure + the three powers with an identity `Default` — via `RollManifest::tone(name)`; the granular getters (`exposure_ev`/`curve`) were dropped once the app read wholly through `tone()`. (The `level_blacks`/`level_whites` fields from the follow-up were removed along with the controls.) **Grid thumbnails reflect edits too**: `decode_next()` reads the full `roll.tone(name)` at spawn and `convert_thumbnail` bakes it all in — the curve powers through the shared `exposure_shader::apply_curve`, then `apply_exposure` (all identity at defaults) mirroring the shader's exact ordering, so grid == detail; `EditSave` additionally re-bakes the selected tile (back to `Thumb::Loading`, then pumps). Opening a file (`ThumbnailActivated`) persists outgoing edits, then reads the stored `ToneEdit` back into the four live values AFTER `clear_detail()` zeroes them and BEFORE `decode_detail_next()` builds the shader (which consumes them via `set_curve`). Saving is per-roll and directory-parameterized (`load_roll_manifest(dir)`, `save_roll_manifest(dir, …)`): each roll directory owns its `.film-roll.toml` sidecar, so multi-roll is structural — the manifest flushes on drill-out (`persist_roll()` on `RollActivated`/`DetailClosed`/`BackToRolls`) and on window close. **Reset all edits** (`ResetAll`) restores those same values, not the identity: `ThumbnailActivated` snapshots the loaded `ToneEdit` into `reset_exposure_ev`/`reset_curve_contrast`/`reset_curve_rolloff`/`reset_curve_shadows`, and `ResetAll` writes the snapshot back to the live values + shader + `roll.edits` (flushed on the usual points), so reset reverts the panel to the state it was opened with — idempotent and anchored (a second reset returns to the same snapshot). `clear_detail()` resets the snapshot fields to identity alongside the live ones, so the next open re-syncs them. `clear_detail()` still resets `exposure_ev = 0.0` and curve to 1.0 — harmless, since every open re-sources from the manifest. Storage is parameterized by directory (`library_dir()`, `load_roll_manifest(dir)`, `save_roll_manifest(dir, …)`), ready for the planned multi-roll feature where the *user* owns file structure and each roll gets its own manifest; the single hardcoded `~/Pictures/exposure` is the POC's one roll. Known trade-off: renaming/moving a file *inside* a roll orphans its edit (the name is the key) — acceptable given user-owned structure; TOML keeps the file hand-editable.

## Architecture (model in `src/app.rs`, GPU in `src/exposure_shader.rs`)

- State: `tiles: Vec<Tile>`; `Tile { name: String, thumb: Thumb }`; `Thumb::{Loading, Ready(Handle), Failed}`. Detail state: `selected: Option<String>`, `detail_shader: Option<ExposureProgram>` (set after one decode, dropped on close/reselect), `detail_inflight: Option<String>` (name handed to the single permitted background decode), `detail_thumb_opacity: f32` (1.0 → 0.0 thumb crossfade), `detail_last_frame: Option<Instant>` (framerate-independent fade timing), `detail_thumb: Option<Handle>` (thumbnail kept visible under the fading hi-res), `exposure_ev: f32`, `detail_zoom: f32` (log2 units ≥ 1), `detail_pan: (f32, f32)` (widget-center-relative physical px), `detail_panning: bool`, `detail_cursor: Option<Point>` (center-relative, kept up to date while hovering so wheel zoom anchors correctly even without a drag), `stock: MonoStock` (non-persisted preview stock driving the GPU remap; reset to `ACTIVE_STOCK` in `clear_detail()`), `roll: RollManifest` (RAM copy of the active roll's manifest, loaded in `RollOpened` and reconciled against the scan), `reset_exposure_ev`/`reset_curve_contrast`/`reset_curve_rolloff`/`reset_curve_shadows` (snapshot of the edit values at panel-open, what `ResetAll` restores), `rolls: Vec<Roll>` (library cards — `Roll { dir, name, cover, frame_count, thumb }`), `active: Option<PathBuf>` (drilled-in roll dir; `None` = library page), `selected_roll: Option<PathBuf>` (single-click library selection — highlight + RollInfo drawer target; preserved across drill-in/back so the highlight and Enter survive a round trip), `frame_selected: Option<String>` (frame-grid highlight: the tile single-clicked or last opened/paged to inside a roll; distinct from the detail `selected` so it survives closing the detail view, drives the accent ring + Enter/arrow nav, reset on roll open/back), `grid_cols: usize` (library grid column count from `on_window_resize`, seeded 3 until the first resize), `cover_inflight: Vec<PathBuf>` (dirs handed to the ≤`MAX_CONCURRENT_THUMBS` cover decodes), `query: String` (toolbar search, filters roll/frame names in `view`), `thumb_inflight: Vec<String>` (names handed to the ≤`MAX_CONCURRENT_THUMBS` permitted thumbnail decodes). Helper methods: `clear_detail()` resets all detail buffers including zoom/pan and the tone preview (`curve_contrast`/`curve_rolloff`/`curve_shadows` → 1.0; re-sourced from the manifest on every open); `handle_detail_ready()` applies a completed decode and re-applies the current zoom/pan + tone curve to the fresh shader; `persist_roll()` flushes `roll` to disk.
- Messages: `RollsLoaded(Vec<Roll>)` fills the library then starts the cover chain; `RollInfoLoaded(Roll)`/`CoverReady(PathBuf, Result<Handle, ()>)` feed card covers (dedup by dir, sorted by name); `AddRoll`/`RollAdded(PathBuf)` open the folder picker and scan + register a new roll (persisting the config list); `RollSelected(PathBuf)` single-click select for the library highlight + metadata drawer; `OpenSelected` (Enter on the library selection — or on the highlighted frame — ) and `RollActivated(PathBuf)` (double-click) drill into a roll through the shared `open_roll` helper (persists outgoing edits, resets detail/editing + `frame_selected`, loads frames; no-ops on the already-active roll and closes a RollInfo drawer); `Nav(MoveDir)` arrow-key selection movement, dispatched by page — library roll selection, open-roll frame highlight, or left/right detail pagination (`MoveDir` = Left/Right/Up/Down); `FrameSelected(String)` single-click highlight of a frame tile (no open); `RollOpened(PathBuf, Vec<String>)` builds its tiles then starts the thumbnail chain (stale-scan guarded against `active`); `BackToRolls` returns to the library (resets `frame_selected`); `SearchChanged(String)` sets the toolbar query; `ThumbReady(String, Result<Handle, ()>)` stores result and chains next; `ThumbnailActivated(String)` opens a frame through `open_frame` (persists outgoing edits, loads stored tone, sets `selected` + `frame_selected`, pumps the detail decoder); `DetailReady(String, Result<(Vec<f32>, u32, u32), ()>)` applies only when `detail_result_is_current(selected, inflight, finished)` — caches the thumbnail for crossfade, builds the `ExposureProgram`, sets `detail_thumb_opacity = 1.0`, then pumps; `DetailFadeTick` advances the thumbnail crossfade; `ExposureChanged(f32)` writes into the shader uniform directly and updates the RAM roll edit (no debounce, no echo message); `EditSave` flushes the RAM roll to the manifest (slider `on_release`, `DetailClosed`, `on_close_requested`); `DetailZoom(f32)` accumulates the wheel delta through `apply_detail_zoom` (pure helper: clamp + re-center-at-fit + anchor) and pushes `set_view` into the shader; `DetailPanPress` starts a grab (`detail_panning = true`, clears focus); `DetailPanMove(Point)` records the center-relative cursor always and, while panning, accumulates the drag delta into `detail_pan`; `DetailPanRelease` ends the grab; `CurveChanged(f32, f32, f32)` writes the new contrast/rolloff/shadows powers into `curve_contrast`/`curve_rolloff`/`curve_shadows`, pushes `shader.set_curve(...)`, and updates the RAM roll edit (live + persisted); `ResetAll` restores exposure + tone curve to the values the edit panel was opened with (a snapshot anchored at `ThumbnailActivated` from the stored manifest, not the identity — RAM + shader + roll edit, idempotent); `DetailClosed` (Escape) clears selection + all buffers + resets exposure/zoom/pan/curve; `Ignore` (no-op) consumes events aimed at the detail view's blocking `MouseArea`.
- Decode chain: `decode_next()` fills up to `MAX_CONCURRENT_THUMBS` slots with distinct `Loading` tiles → one `tokio::task::spawn_blocking` per file (`decode_thumbnail`), returned as a `Task::batch`. Bounded concurrency keeps a handful of full-res RAW buffers alive at a time (each is released once it finishes downscaling) instead of one — several parallel decodes on multicore. `thumb_inflight` (a `Vec`) enforces the cap and de-duplicates: a name already running is never spawned again, so a re-bake requested mid-chain waits for its decode instead of racing it, and the EV + tone curve are read at spawn time — startup tiles bake stored edits, re-baked tiles bake the freshest. `ThumbReady` removes the finished name and pumps; `RollOpened` clears the set (fresh roll = fresh chain), `BackToRolls` drops it, `RollsLoaded` clears it alongside a new roll round. Roll covers are pumped by the sibling `decode_covers()` — same cap/discipline, keyed by dir via `cover_inflight`, cover EV always 0.0.
- Detail pump: `decode_detail_next()` spawns only when no decode is in flight and something is selected. **Progressive two-level loading through the single slot**: with no shader yet it decodes the 2048 overview; once `detail_zoom ≥ NATIVE_ZOOM_THRESHOLD` the first wheel past 2× contain spawns a native-cap re-decode (`MAX_TEXTURE_EDGE` = 8192) whose arrival swaps the texture in place — `fresh_open` (shader absent) gates the thumbnail fade so a level-up never re-flashes the thumb, and the swap re-applies the current zoom/pan + tone curve so framing holds. `detail_native_queued` makes the level-up one-shot (`DetailZoom` trigger + the flag gate), and is set early when the sensor's true long edge (post-crop, pre-downscale — `src_long_edge`, threaded out of `decode_raw_detail`) never exceeded `HI_RES_SIZE` (≤ 2048 — nothing bigger exists). The native-ness decision must use that *source* edge, NOT the capped overview width: a large sensor downscaled to just under 2048 would otherwise be mistaken for a small one and the level-up permanently suppressed (the original `2047 < 2048` false-positive that broke 18MP files). A superseded decode's arrival frees the slot via the stale guard and re-pumps. **Landing-time re-pump**: a trigger fired into an *occupied* slot is silently swallowed, so if the user wheels past the threshold while the overview is still decoding, `handle_detail_ready` re-checks the trigger right after freeing the slot (on the `Ok` landing only — an error landing never spins the slot) and starts the native level for the now-loaded overview. Failures do NOT auto-retry (re-selecting the file retries on demand; after an `Err` landing the zoom trigger stays live, so the next wheel retries).
- Thumbnail pipeline (`convert_thumbnail(image, max_size)`): `rawloader::decode_file` → `downsample_thumbnail` (fused normalize + crop + phase-preserving block average straight from the sensor buffer: bayer classes rescaled onto one common base per `class_gains`, cpp≥3 via luma-of-channel-means) → `film::measure_base` + `film::invert_gray` → `unsharp_mask` (linear light) → `tone_anchors` + `apply_curve` (the three pivoted powers) → `apply_exposure` (`2^EV`) → `srgb_encode` → u8 quantize as `[v,v,v,255]` → `orient` → `Handle::from_rgba`. The tone bake mirrors the detail shader's ordering exactly (curve → exposure → clamp → sRGB); all identity at defaults. (Detail path keeps the *separate* full-res steps — `normalize_samples`, `crop_samples`, `flatten_bayer`/`luma`, `resize_area` at the level's cap — `HI_RES_SIZE` for the overview, `MAX_TEXTURE_EDGE` for the native level-up — untouched: two-ish near-duplicate pipelines, one fused for thumbs, one full-fidelity for the GPU.)
- Detail pipeline (`decode_raw_detail`): same as the thumbnail pipeline through `unsharp_mask` on `Vec<f32>` mono, then `orient_mono` (per-element float mirror of `orient`) and `Ok((mono, width, height, src_long_edge))` — the extra field is the sensor's true long edge after cropping, before the downscale, which `handle_detail_ready` uses to decide whether the overview was already native. The downscale cap is a parameter (`max_edge`): `HI_RES_SIZE` at the overview level, `MAX_TEXTURE_EDGE` at the native level-up; `resize_area` treats a cap ≥ both source edges as identity (`scale` clamps to 1.0), so ≤8K and small sensors decode at true full resolution — the small-scan overview simply marks the level-up done. No CPU-side sRGB encoding, no RGBA packing, no `Handle::from_rgba`. The GPU shader does sRGB encoding per fragment.
- **GPU pipeline** (`Pipeline::new` in `src/exposure_shader.rs`): one-time creation of `ShaderModule` from `include_str!("shader/exposure.wgsl")`, `BindGroupLayout` (texture, sampler, uniform buffer), `PipelineLayout`, `RenderPipeline` (fullscreen triangle, target format `Bgra8Unorm` to match iced's framebuffer on this libcosmic configuration), `Buffer` for the `Uniforms` struct, and a `Sampler` (linear + ClampToEdge). The texture + bind group are created lazily in `Primitive::prepare` on the first frame because they need the mono data. Subsequent frames: only the uniform buffer is updated via `queue.write_buffer`. The WGSL `fs_main` already applies `linear_to_srgb` per fragment, so the target is `Unorm` (linear) rather than `UnormSrgb` — picking `UnormSrgb` would double-encode. The `_format` parameter iced passes is ignored; if libcosmic ever switches to an sRGB-aware framebuffer, this would need a paired change (drop `linear_to_srgb` from the shader or no-op it, then swap the target back to `Bgra8UnormSrgb`).
- WGSL uses the canonical 3-vertex fullscreen triangle (`-1,-1 / -1,3 / 3,-1`) with NDC values passed through directly. Earlier pattern `(vec2(1u, 2u) + vi) % vec2(6u) < vec2(3u)` produced only the upper-right half of the viewport (visually a triangle), because under wgpu the render-pass scissor clips to the viewport rect rather than to the original primitive's bounds.
- `Uniforms.exposure` carries `2^EV` (linear-light gain), NOT the raw EV. `Primitive::prepare` computes the gain once per slider change via `f32::exp2`. At EV=0 the gain is exactly 1.0 (identity). Sending raw EV would render black at EV=0 and over-bright at EV≥1 because the shader's `mono_linear * exposure` would multiply by the slider value instead of the matching gain.
- Texture re-upload is keyed by `image_id: u64` so selecting a second image actually rebuilds the GPU texture and bind group. `AppModel.next_image_id` is a `wrapping_add(1)` counter stamped onto `ExposureProgram::image_id` in `handle_detail_ready`; `ExposurePipeline::current_image_id: Option<u64>` remembers the last installed id. Without this, iced reuses the same `ExposurePipeline` across image selections (it caches by `TypeId`) and the previously-uploaded mono data stays bound to the new shader — visible as "second image still shows first".
- Detail view layout: the shader widget is `Length::Fill × Length::Fill` directly inside a Fill × Fill `widget::container` — no wrapping Grid. Because `widget::Shader` has no `.content_fit()` setter, the WGSL shader does `ContentFit::Contain` math itself (`contained_uv` in `exposure.wgsl`): compares `cell_aspect` against `tex_aspect` and remaps UV to the contained sub-rectangle. **Letterbox/pillarbox bars are alpha-blended (`vec4(0, 0, 0, 0)` + `BlendState::ALPHA_BLENDING`) so the COSMIC panel background shows through** rather than rendering solid black frames. Earlier approach with `Grid::with_capacity(1).height(Sizing::AspectRatio(1.0)).columns(1)` failed because the Grid reports widget bounds = `(available_width, available_width)` and iced_wgpu's `Primitive::render` uses `instance.bounds ∩ physical_bounds` for `set_viewport` — not the parent's clipped viewport — so when `available_width >` the column's available height the shader painted pixels in the header. The Fill × Fill path keeps the shader widget bounded at the parent column's allocation; no overflow.
- **Per-frame uniform** (48 bytes, `Uniforms` struct, matches WGSL): `exposure: f32` (= `2^EV`), `tex_w, tex_h: f32` (texture dimensions for the WGSL contained math), the fragment-shader-readable scissor rect expressed in physical pixels (`sc_x, sc_y, sc_w, sc_h` — computed from `bounds.{x,y,width,height} × viewport.scale_factor()`), `zoom: f32` (log2 units, 1 = contain), `pan_x, pan_y: f32` (image-center displacement, **physical** pixels — `prepare()` multiplies the logical pan by `viewport.scale_factor()`), and `curve_ratio, curve_exp: f32` (the composed tone remap `ratio·p^exp` from the three pivoted power curves — see the `curve_remap` bullet; identity at the 1.0 defaults). The layout is 12 f32. The shader's `view_uv` replaces `contained_uv`: `scale = min(sc_w/tex_w, sc_h/tex_h) · 2^(zoom−1)`, then the centered box is displaced by pan; fragments outside the moved box output alpha 0 (same blend trick as the bars), so panning past an edge shows the panel background rather than clamped pixels.
- Constants: `THUMB_SIZE = 384.0` (decode cap + grid cell), `HI_RES_SIZE = 2048` (detail overview decode cap), `FADE_SPEED = 5.0` (thumb-fade-out units/second, ~0.2 s ramp), `TILE_ASPECT = 1.0`, `UNSHARP_AMOUNT = 0.4`, `BASE_SAMPLE_TARGET = 250_000`, `MAX_CONCURRENT_THUMBS = 4`, `MAX_DETAIL_ZOOM = 7.0` (≈64× contain), `NATIVE_ZOOM_THRESHOLD = 2.0` (level-up trigger, log2 units), `MAX_TEXTURE_EDGE = 8192` (native level-up cap, wgpu's typical texture ceiling).
- View: a column (spacing `space_s`) of a fixed `controls_row()` toolbar on top and the page body below. The toolbar holds back ("←", only while a roll is open) or Add roll, plus a `search_input` that filters by case-insensitive substring. The library body is `Grid::with_children(rolls.map(roll_tile)).fluid(THUMB_SIZE)` + `.height(grid::Sizing::AspectRatio(TILE_ASPECT))` inside a scrollable that wraps the grid in `widget::container(grid).width(Length::Fill).padding(space_s)` — the 16px inset matching the toolbar's own `space_s` padding (this iced fork's `Scrollable` has no `.padding()` builder; the inner container supplies it). Each card is one interactive unit: an outer `MouseArea` (`on_press(RollSelected)` + `on_double_click(RollActivated)`) wraps the whole card — a full-bleed cover, title, and the `roll-frames` caption (`text::caption`, localized plural "{count} frame(s)" from `Roll.frame_count`) — so single-click selects and double-click opens anywhere, even on a still-decoding cover. The cover is flush to the card's top edge with no padding and uses `content_fit(ContentFit::Cover)` + a **top-only** `border_radius(border::Radius::default().bottom(radius))`: iced-wgpu's image shader clips fragments to a rounded-box SDF, so the card's top corners genuinely cut into the photo while the cover's bottom corners stay square (interior edge). The bottom-call is deliberate — the pinned image shader applies its `vec4` radius rotated 180° from `border::Radius`'s struct order (first two entries render on the bottom), so the top clip is expressed via `.bottom()`. `radius` comes from `cosmic::theme::active().cosmic().corner_radii.radius_s[0]`, so the clip matches the COSMIC system Roundness setting (rounded/slightly-rounded/square) exactly as `Container::Primary` resolves it — nothing hardcoded. Landscape crops ~nothing; portrait center-crops top/bottom. Title + caption sit in an `info` container padded `space_xs` (12px) all round, whose top padding is also the cover→text gap (the card column uses `.spacing(0)`); cover placeholders (`image-loading/missing-symbolic`) stay centered in the same Fill×Fill sheet. **Selection is an overlay, not a card style**: the card sits in a `Stack` on a `Container::Primary` surface (radius from the theme), and a selected card gets a transparent `Container::custom` overlay ring on top — accent border 2.0 wide, radius `radius_s` — so the full-bleed cover can never hide the highlight (iced paints a container's border *behind* its children; the prior card-border highlight was exactly that, and the full-bleed image covered the top/left/right segments). The ring is decorative (no `MouseArea`), so it never eats the card's clicks. Cover fallbacks stay `image-loading/missing-symbolic`; `no-rolls`/`no-rolls-found` empty states and the library selection grid navigation (`grid_cols` column math) are unchanged, mirroring the same `Grid::fluid` layout. Drilled in, the body becomes the frame grid built by `cosmic::iced::widget::Grid::with_children(tiles.map(tile_view))` with `.fluid(THUMB_SIZE)` + `.height(grid::Sizing::AspectRatio(TILE_ASPECT))`, wrapped in `scrollable(container(grid).width(Fill).padding(space_s))` (the same 16px frame), filtered by the toolbar search with a `no-files` empty state. Frame tiles are selectable like the library cards: a single `MouseArea` (`on_press(FrameSelected)` + `on_double_click(ThumbnailActivated)`) wraps the whole tile — `Contain` image (never cropped, so a film frame's full framing stays visible) over a `space_s`-padded name — on a `Container::Primary` surface, with the same shared `selection_ring()` overlay on a `Stack` when `frame_selected` matches. `detail_view()` is pushed onto a `Stack` OVER the always-mounted grid (bottom: grid scrollable; top: detail in an opaque window-background container) instead of replacing it — the grid keeps its scroll state and stays interactively off-limits via a blocking `MouseArea`, while the preview surface itself is the interactive `DetailArea` (wheel zoom, grab-pan) nested inside the blocker: iced delivers to the inner widget first so its `capture_event()` wins for events over the preview, and the blocker's `Ignore` handlers remain effective over the caption/bars. The preview is an iced `Stack` with the GPU `Shader` as the bottom layer and `detail_thumb` on top with `.opacity(detail_thumb_opacity)` (later children draw over earlier ones; the thumb fades out from 1→0); once the fade completes the thumb is dropped and the shader shows alone. The detail view fills the full content width; the editing panel is the COSMIC context drawer in side-pane mode. COSMIC left toggle (View menu) holds About + Roll info (`MenuAction::RollInfo` bound to `Ctrl+Space` in `key_binds` and gated on a library selection).

## Known limitations (likely next-step targets)

1. **Tone editing is manual, not a stock**: the fixed inversion stock is `film::ACTIVE_STOCK` (HP5+). The editing drawer is a *persisted* manual contrast/rolloff/shadows control (see the Tone model + Edit persistence bullets), not yet a picker of real `MonoStock`s (each a tuned `(d_max, gamma)` preset that could drive the same `(ratio, exp)` uniforms). The parametric D-max/gamma fiction was dropped deliberately (it collapsed into a duplicate of exposure; see the Tone model bullet). Cast WB stays self-calibrated per image from clear-film plateaus, so margin-less frames rely on the `MIN_PLAUSIBLE_BASE` fallback. Natural next steps: calibrate-base-from-base-only-frame feature (`measure_base` does the math), AsShot-WB prior for margin-less frames, color stocks using `invert_mono`/`measure_base_channels`.
2. **No live refresh**: re-adding a roll re-scans it (Add roll doubles as a manual refresh), but an open roll's frame list is fixed for the session and the library list has no global rescan button.
3. **Memory unbounded** across many decoded thumbs (no LRU/eviction); ~600 KB each. Detail view holds one oriented mono `Vec<f32>` (~16 MB at 2048×2048 f32) + its GPU texture; zooming past the threshold re-decodes it at native cap (`MAX_TEXTURE_EDGE`), so a >8K sensor transiently holds up to a `long_edge ≤ 8192` mono buffer (~0.5 GB worst case at 8192² f32) until the old buffer is dropped on swap. All buffers are dropped on close/reselect.
4. Decode errors are silent (`Err(())`); non-RAW files are listed and show the missing icon. A failed hi-res detail decode likewise keeps showing the thumbnail — selecting another file and back retries on demand.
5. **Grain/noise/sharpness**: area-average downscale, luminance collapse, full-res bayer flattening, gentle unsharp mask — plus the post-decode bandwidth savings on the GPU side (one linear texture upload vs. a continuously-re-encoded sRGB image). Remaining stackable option — a denoise pass for very underexposed captures. Capture-side: scans exposed with clear film far left in the histogram waste SNR; exposing so the base sits near saturation (~85–95%) keeps several more stops of detail in dense areas.
6. **Exposure EV precision**: the exposure edit is stored in the manifest and pushed to the GPU uniform as `f32` (`Uniforms.exposure`, `EditData.exposure_ev`), but the slider only spans −3..+3 EV at 0.01 steps (~600 discrete values). Revisit whether the accuracy/width is justified — e.g. a fixed-point or narrower type in the manifest, or whether the shader could take the EV precomputed as f16 via `R16Float`-style storage rather than f32.
7. **GPU vs CPU for thumbnails (decided: CPU)** — evaluated when wiring edit-aware tiles. GPU does NOT help thumbnail *loading*: `rawloader::decode_file` is the dominant cost and is CPU-only; the quality-relevant steps (full-res `flatten_bayer`, linear-light area-average downscale) are intentionally CPU-side because a GPU sampler can't do area-average (mip/bilinear differs), and uploading full-res mono per tile would be ~100 MB/tile. The GPU-able tail (EV multiply + sRGB + quantize at ≤384 px) is trivial CPU, so per-tile shader objects buy nothing. GPU stays where it already pays: the single live detail shader. Consequence taken instead: thumbnails are *re-decoded* CPU-side with the EV baked in on edit release — one RAW re-decode per edited file, background + bounded-concurrent, so the grid updates a beat after the detail view. If instantaneous grid feedback were ever required, the alternative is caching the un-exposed linear mono per tile (~590 KB @ 384 px f32) and re-encoding on edit — rejected now because it breaks the memory-boundedness that the concurrency cap/no-cache currently guarantees (see #3). The accepted flatten-before-average tone swap (per-class bases measured at thumbnail scale after averaging) plus the ≤4-way decode concurrency (transient RAM peak ≈ `MAX_CONCURRENT_THUMBS` decoded full-res buffers) are the current price of the speedup; `CONCURRENT_THUMBS` is a one-line knob.

## Environment gotchas

- `libcosmic` is a plain git dependency on pop-os master; lockfile pins `ef490df5`. The local clone at `../cosmic/libcosmic` is no longer patched in. Upstream includes the old `AspectRatio::layout` off-by-one fix and iced's `Grid` export. The commented `[patch]` template in `Cargo.toml` can restore the clone if needed.
- The `wgpu` feature on libcosmic is required for `iced::widget::shader::Shader`. Without it the `ExposureProgram` won't have a `Pipeline::new` entry point.
- Verify changes with `just check` (clippy pedantic) and `cargo test --locked`. Expect ~130 warnings from compiling libcosmic master from source — ignore those; only warnings pointing into `src/` matter.
- Detail-pump diagnostics: run with `EXPOSURE_TRACE_DETAIL=1` (default-off, in `AppModel` via `detail_trace`) to log the two-level decode lifecycle to stderr — trigger fire/swallow with the cap, arrival dims + `fresh_open`, decode errors, and landing re-pumps. One instrumented run settles whether a missing level-up was a swallow (fixed by the re-pump), a decode `Err`, or a swap that never rendered.
- `bytemuck` is the only binding-layer shim (Pod/Zeroable impls on the `Uniforms` struct); `wgpu` itself comes through libcosmic's vendored re-export. `rayon` was previously a direct dep for CPU exposure re-encoding; it stays only as a transitive of `rawloader`.

## Useful API facts (verified against pinned libcosmic/rawloader)

- `cosmic::Task<M>` aliases `iced::Task<cosmic::Action<M>>`; async work: `cosmic::task::future(async { Message::X(...) })`; batch with `Task::batch([...])`.
- `rawloader::{RawImage, RawImageData, Orientation}` are re-exported at crate root (`decoders` module is private).
- `RawImage` fields used here: `width`, `height`, `cpp`, `data`, `wb_coeffs` ([f32;4] RGBE), `blacklevels`/`whitelevels` ([u16;4]), `orientation`, `cfa`.
- `rawloader::CFA` is crate-exported; `CFA::new("RGGB")` builds test patterns; `color_at(row, col)` mods internally (`(row+48)%48`), so any coordinates are safe. Returns 0=R, 1=G, 2=B, 3=fourth-color. `shift(x, y)` re-phases the pattern after cropping by `(left=x, top=y)`.
- `RawImage.crops: [usize;4]` is `[top, right, bottom, left]`. Tested Canon CR2s flag top/left only; their LAST two sensor rows also read elevated (~9k vs ~2k ADU) despite `bottom=0` — if a bottom-edge artifact ever appears, suspect unflagged masked rows.
- Icons: `icon::from_name("...").icon().into()` yields an Element; image handles clone cheaply. `widget::icon::from_name(...)` returns a `Named` with `From<Named> for icon::Handle`, so `.leading_icon(widget::icon::from_name(...))` works on buttons.
- **Roll library widgets** (verified against pinned libcosmic): `cosmic::dialog::file_chooser::open::Dialog::new().open_folder()` is async (xdg portal via ashpd), returns `FileResponse` whose `url()` is a `&Url` (path via `to_file_path()`); `Error::Cancelled` covers cancel/portal failure. No public dialog title setter exists in the pinned libcosmic, so the picker is invoked title-less. `widget::search_input(placeholder, value)` (`widget/text_input/input.rs:91`) returns a `TextInput` with `.on_input(Message)` and its own `system-search-symbolic` leading icon. `cosmic::Application` must be `use`d for `Self::APP_ID`/`core_mut()` inside plain `impl AppModel` blocks.
- **iced `widget::shader`** (verified against pinned vendored iced): reach through `cosmic::iced::widget::shader::{Pipeline, Primitive, Program, Shader, Viewport}`. `Shader::new(program).width(Length::Fill).height(Length::Fill)` wraps a `Program` impl. `Program::draw()` produces a `Primitive`; `Pipeline::new()` is called once when iced first sees a new pipeline type; `Primitive::prepare()` runs every frame; `Primitive::render()` runs every frame and uses an `encoder.begin_render_pass(...)` with `LoadOp::Load` (we draw into an already-painted framebuffer). `viewport.physical_{width,height}()` and `bounds.{x,y,width,height} × viewport.scale_factor()` give physical-pixel coordinates for the scissor region.
- **Other iced widget traits** verified for this feature: `MouseArea::new(content).on_double_click(message)` (takes a message value, not a closure); `cosmic::iced::keyboard::listen()` delivers only keyboard events widgets did NOT capture (Status::Ignored) — fine for a global Escape; `Subscription::filter_map` requires NON-CAPTURING closures (`Fn(T) -> Option<A> + Clone`); `cosmic::iced::widget::Stack::with_children([...])` layers children bottom-to-top in push order — used here for thumb-over-shader layering. `Rectangle::center()` (iced/core `rectangle.rs`) and `Cursor::position_in(bounds)` (cursor.rs) power `DetailArea`'s center-relative reporting; `ScrollDelta::{Lines, Pixels}` (iced/core `mouse/event.rs`) is what `on_scroll` receives — a wheel notch gives `Lines { y: ±1 }`, trackpads give `Pixels`.
- **Pure testable helpers**: the zoom/pan messages route through `apply_detail_zoom(zoom, pan, cursor, delta)` and `zoom_about_anchor(z0, z1, pan, cursor)` — no app state, so the pinned-point/round-trip/re-center invariants are unit-tested (`app.rs` tests). `detail_zoom_delta` maps `ScrollDelta → log2` units. The tone model is likewise pure: `curve_remap(contrast, rolloff, shadows, shadow, mid, white)` composes the three pivoted powers into `(ratio, exp)` and `tone_anchors(mono)` measures the 10th/50th/98th-percentile anchors from a histogram — unit-tested for identity-at-defaults, per-control pivot-pinning (`T(mid)=mid`, `T(white)=white`, `T(shadow)=shadow` at identity-others), exact three-power composition (single final clamp, matching the shader), and the degenerate-black guard (`MIN_ANCHOR`). The WGSL itself is validated in `exposure_shader::tests::wgsl_source_parses_and_validates` via a `naga` dev-dependency (already in the lockfile through wgpu, so nothing new compiles) — the shader is compiled by wgpu only at first launch, so a parse regression would otherwise surface only at runtime.
- **WGSL shader** (verified with vendored wgpu 28): `vertex_index` builtin provides 0..2; the per-vertex fullscreen-triangle pattern `vec2<f32>((vec2(1u, 2u) + vertex_index) % vec2(6u) < vec2(3u))` is the standard 3-vertex covering-trick; the render pass viewport is set to the primitive's bounds via `pass.set_viewport(...)` so NDC [-1..1] maps to the rect.
