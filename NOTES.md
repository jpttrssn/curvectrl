Reference for continuing work on the roll library (rolls ↔ frame grid ↔ detail view navigation), thumbnails, and the GPU detail pipeline.

Accessible via **Edit → Calibrate base from this frame / Auto base per frame / Use preset base** (roll-scoped, enabled while an inverted roll is open). See `raw_ev.md` part 3.
- **#14 One shared CPU bake tail + GPU tone LUT** — grid thumbnails, exports, and the detail shader now share a single tone pipeline: `app::bake_tone` (`pivots_for` measures + `render_tail` applies) replaced the duplicated inline sequences in `convert_thumbnail` and `export_one`, and the inverted (film) CPU bake derives its pivots EV-exact from the raw sensor fractiles (`film_anchor_fractiles` + `film_pivots_at_gain`, the latter now `pub(crate)`) exactly like the detail shader. The per-pixel tone math is now single-sourced in `shader::tone_model` (`clamp(ratio·p^exp,0,1)`, fed by `curve_remap`); the WGSL no longer contains it — `shade()` texture-samples a 2048×1 `R16Float` tone LUT (`build_tone_lut`) that `DetailProgram` rebuilds on every curve/EV change (`rebuild_tone_lut`, `tone_version` → `prepare()` re-uploads ~4 KB). The LUT is sampled on the gamma domain `t = p^(1/2.2)` (so the grid packs toward black where shadow-lift curves are steep) and stores `curve × 512` (half-float's low end would otherwise flush pre-exposure values the CPU bake preserves). CPU bakes call `tone_model` exactly, so the only approximation anywhere is the LUT itself — bounded by `tone_lut_reproduces_tone_model_within_tolerance` (≤1e-3) and `cpu_bake_matches_gpu_lut_simulation_on_random_frames` (≤5e-4 over randomized frames/EV/curve/preset/base-mode, simulating the GPU via `sample_tone_lut_f32` + `half_to_f32`), replacing the manual detail-vs-export eye-check. `curve_ratio`/`curve_exp` left the `Uniforms`/WGSL structs. `cargo test --locked`: 195 passed, 0 failed; `just check`: the same 8 pre-existing warnings.
- **#8 File & Edit menus** — header now has File (Add/Remove roll + Quit), Edit (Select all, Copy edits, Paste edits), and View (About, Details) menus, fully wired through `MenuAction` → `Message`. The menu bar is `window_id_maybe(main_window_id)` + `on_surface_action(Message::Surface)` (cosmic-files' wiring): `Message::Surface` forwards to `cosmic::app::Action::Surface`, so menu popups are real Wayland surfaces rather than the in-window overlay (which per the pinned libcosmic would not paint until the next mouse move — upstream commit `3b62210`).

## File layout

- `src/app.rs` — UI (tiles, detail crossfade, editing panel), async decode pump, all RAW/image helpers (mono reconstruction, base measurement, resize/unsharp, orient).
- `src/shader.rs` — `DetailProgram` implementing `iced::widget::shader::{Program, Primitive, Pipeline}` for the detail view.
- `src/edit_manifest.rs` — per-roll edit persistence: `RollManifest`/`EditData`/`ToneEdit` (serde+toml), the `.film-roll.toml` sidecar reader/writer (atomic temp+rename), `reconcile`, unit tests.
- `src/exif_writer.rs` — EXIF writing for exports: `shifted_datetime` (ISO date + seconds), the hand-rolled TIFF blob (`build_tiff`), and the JPEG APP1 splice (`jpeg_app1`/`splice_after_soi`); PNG's `eXIf` is written via the `png` crate directly. No new crates; its unit tests round-trip through `exif` (kamadak-exif).
- `src/config.rs` — persisted app config (cosmic-config derive, schema v2): the roll list `rolls: Vec<String>` (absolute roll directories).
- `src/shader/exposure.wgsl` — fullscreen-triangle WGSL that samples a linear mono `R16Float` texture, applies the sensor-space `2^EV` gain (for an inverted/film preset the gain is `2^-EV` and the fragment ALSO density-inverts the transmission first — `curve(invert(s·2^-EV))`), re-shapes the positive via the CPU-built 2048×1 tone LUT (`t_tone`, sampled on `t = p^(1/2.2)` and divided by the 512× pre-scale — the tone model lives only in Rust `tone_model`, so the WGSL never changes for tone work), sRGB-encodes, and maps fragments through a zoom/pan transform (`view_uv`).
- `src/film.rs` — density-space mono inversion + base measurement (`MonoStock`, `ACTIVE_STOCK` = Ilford HP5+).
- `src/detail_area.rs` — `DetailArea` widget: an iced-`MouseArea` clone that reports cursor positions relative to the widget **center** (needed by the zoom-anchor math), fires `on_release` when the cursor leaves while pressed (iced suppresses release outside bounds), and stays stateless (`tree::State::None`). A11y nodes omitted (the trait default covers it; no direct `iced_accessibility` dep).

## Current behavior

- **Library page**: the configured film rolls (config key `rolls`, a `Vec<String>` of absolute directories) are listed as cover cards in a responsive grid sorted by roll name. There is no library toolbar: the search lives in the COSMIC header bar (`header_end`) as an **icon-toggled** `search_input` mirroring cosmic-files (see the View bullet), and an **Add Roll** tile (the label above a `list-add-symbolic` icon on a `Container::Primary` card, matching the other tiles) is always the first grid cell and is a **fully selectable cell like any roll card**: a **single click** selects it (accent ring, the shared `selection_ring()`), and a **double-click** (or **Enter** while it's selected) opens the system folder picker (`cosmic::dialog::file_chooser::open::Dialog::open_folder()` via `open_roll_picker()`/`Message::AddRoll`). Re-adding an existing roll still re-scans it, so the tile doubles as a manual refresh. A **single click** selects a roll (the whole card highlights with an accent border — see the Library page tile bullet — and it becomes the metadata-drawer target); Enter or a **double-click** anywhere on the card drills into its frame grid. Each card shows a full-bleed cover (crop-filled to the card, clipped at its top corners), the title, and a frame-count caption. Roll covers decode through the same thumbnail pipeline **baking in the cover file's stored exposure and tone edits from the roll's manifest** — so the roll tile preview mirrors the edited frame (an untouched roll decodes at the identity exposure/curve, byte-identical to before). When there are no rolls (or the search matches none), the empty-state hint centers over the space the grid leaves empty while the Add Roll tile stays first and clickable.
- **Keyboard grid navigation**: the subscription's `keyboard::listen` filter routes Escape, Enter, and the arrow keys (`Nav(MoveDir)`). On the **library** page arrows move the selection by the `grid_cols` row size tracked from `on_window_resize` (mirroring `Grid::fluid`'s `ceil((width + spacing)/(max + spacing))`; `grid_cols` seeded to 3 until the first resize), Left/Right step within a row without wrapping, Up/Down jump a full row clamped to the edges, and a selection-less press lands on the first item (`nav_target`, pure + unit-tested); the selection is `LibrarySelection::{AddRoll, Roll(PathBuf)}` and nav indexes the unified `library_cells(rolls, query)` set via `library_cell_index`, so the add tile is a reachable cell 0 and scroll/Enter stay aligned with the rendered grid (the old render-vs-nav off-by-one is gone). The Add Roll tile leads the grid only while **no search is active** — a non-empty/whitespace-trimmed query hides it (`library_cells` prepends it purely on `query.trim().is_empty()`), so an all-missing search yields an empty cell set and `nav_target` returns `None`. Enter opens the selected cell (`OpenSelected` → a roll drills in via `open_roll`, the Add Roll tile opens the folder picker via `open_roll_picker()`). The library **pre-selects** the first visible roll (respecting the search filter) whenever nothing is selected — on `RollsLoaded` and after `remove_roll` clears the removed roll's selection (`select_first_visible_roll`, no-op while a roll is open) — so the library never idles without a roll highlighted; a freshly added roll skips this and drills straight into its frame grid instead, with the selection pinned to it for when you back out (see #20). Inside a **roll**, arrows move the frame highlight over the same filtered set (`grid_cols` reused — the grids share `Grid::fluid` math), Enter opens the highlighted frame (`open_frame`); with the **detail view open**, Left/Right page through the frames instead (`paginate`, clamped, no wrap; Up/Down inert), opening the neighbor in place without closing first. A **bare `Space`** (no modifiers) toggles the active page's **context drawer** — the editing panel while a detail view is open, the Roll info drawer on the library page (no-ops without a roll selection) — the spacebar carries no `Named` variant in this iced fork, so the subscription matches the `Character(" ")` payload with a bare (no-modifier) guard; this replaced the old Ctrl+Space binding and the full-screen preview feature (which used bare Space) was **removed** — Ctrl+Space is now unbound. **Ctrl+F** activates the search field (`Character`+`control()` binding, `SearchActivate`). Escape first deactivates an active search (hiding the input back to the icon), then closes the library drawer, then on a detail view with the editing drawer open closes just the drawer (the detail view survives), then closes the detail view, and on the bare grid backs out of the roll **directly** in one press (the frame highlight is dropped as part of the roll reset — there is no intermediate de-select step). Navigation targets the visible set (`filtered_rolls`/`filtered_tiles` share the header search query, so arrows move over what's actually on screen). **Scroll-into-view**: whichever grid is mounted reports its geometry via `.on_scroll(Message::GridViewport)` into the cached `grid_viewport: Option<Viewport>` (cleared on roll open/back), and `Nav` then reveals a selection that steps beyond the visible area — `nav_cols()` derives the exact column count from the viewport width (iced's `ceil((avail+spacing)/(max+spacing))`), the pure `reveal_target_y` computes the content-space target (`top < offset` → scroll up to `top`; `bottom > offset + viewport_h` → scroll down to `bottom − viewport_h`, clamped to `[0, content_h − viewport_h]`), and the handler returns `scrollable::scroll_to::<cosmic::Action<Message>>(id, AbsoluteOffset { x: None, y })`. Grid ids are `rolls-grid`/`frames-grid` (`scrollable_id`, only one page mounted at a time). Before the first real scroll the viewport is estimated (offset 0, `window_height − 80` from `on_window_resize`, content from the row count); the programmatic scroll itself refires `on_scroll` and takes over precisely.
- **Roll info drawer**: `ContextPage::RollInfo` renders a `context_drawer` pane (same mechanism as editing) listing the selected roll's name (heading), full path, frame count, and cover file name (or `no-cover`), from a `roll_cover_and_count` scan folded into `load_roll` (`Roll::frame_count`). The drawer needs a **roll** selection: both the **View → Details…** menu item and the Space toggle no-op without a `LibrarySelection::Roll` (an Add Roll selection has no metadata, so it behaves like no selection), it never opens while a roll is open (`active.is_some()` → `None` in `context_drawer()`), and a roll selection that leaves the config (e.g. on a re-scan in `RollsLoaded`) drops the selection and closes the drawer.
- On entry, an open roll's frame grid lists every regular non-dot file in the roll directory as tiles, sorted by name (dotfiles — including the edit manifest or its temp — never become tiles). The header search now filters frame names. Fresh configs start with an empty roll list (in memory only — a real config write happens only when a roll is added); the user adds the first roll via the Add Roll tile.
- Columns adapt to window width; cells never exceed `THUMB_SIZE` px wide and stay square (`Grid::fluid` + `Sizing::AspectRatio(1.0)`).
- Each tile: image area (fills its square cell, `ContentFit::Contain`) + file name below. `image-loading-symbolic` / `image-missing-symbolic` icons for pending/failed.
- Thumbs are rendered via the film pipeline: **linear-light phased downscale straight from the sensor samples** (one fused pass — `downsample_thumbnail`: normalize + drop masked borders + per-CFA-class block averages, never materializing a full-res buffer; RGB sources collapse through the Rec.709 luminance of each block's channel means, which is exact because luma is linear) → unsharp (sensor space) → the shared `bake_tone` tone tail (EV-exact film pivots from the raw sensor fractiles, then curve → exposure → sRGB — see #14) → u8 quantize as `[v,v,v,255]` → `orient` → `Handle::from_rgba`. Unsharp mask (`UNSHARP_AMOUNT`=0.4, [1,2,1]² blur) runs on the small mono before exposure, as before. Accepted tone swap: per-class bases and the invert anchor are measured at thumbnail scale after the downscale instead of on full-res samples (flatten-before-average), so high-contrast blocks can differ subtly from the detail render.
- `src/film.rs`: `MonoStock { name, base, d_max, gamma }`; `ACTIVE_STOCK` = Ilford HP5+ (`base=0.82`, `d_max=2.4`, `gamma=0.7` — pending visual tuning). Inversion (shared `positive()` helper): density `log10(base/v)` → normalized position `clamp(density/d_max, 0..1)` → tone curve `position^gamma`. Clear film prints black, the d_max limit prints white. `MIN_PLAUSIBLE_BASE` (0.1) guards against images with no measurable margins.
- Thumbs decode progressively, up to `MAX_CONCURRENT_THUMBS` (4) in flight at once on the blocking thread pool, in file order.
- **Detail view**: double-clicking a tile's image overlays a detail view for that frame on an opaque surface that hides the still-mounted thumbnail grid (the grid never leaves the widget tree, so iced preserves its scroll position across open/close — no snapshot/`snap_to` needed). The detail surface is painted with the window background color (`theme.cosmic().background(false).base`) so the letterbox bars show the same backdrop as before; a full-surface `MouseArea` (`Message::Ignore` on press/release/double-click/scroll) swallows pointer input over the caption/bars so nothing reaches the grid behind, while the preview itself is the interactive `DetailArea` (see Zoom & pan below) (`Length::Fill`, `ContentFit::Contain`, file name caption); Escape returns to the grid. While the GPU decode lands, the cached 384 px thumbnail is shown; once the shader is ready, the thumbnail fades OUT 1→0 over `FADE_SPEED = 5.0` (driven by a `time::every` animation subscription) so the GPU mono texture takes over without a flicker. Earlier approach (`hi_res fading IN over thumbnail`) was flipped because the GPU render is bottom-to-top in `Stack` and the shader is the final layer. Escape closes the view and drops all detail buffers (the overview LRU survives — see the Detail pump bullet). Only ONE critical hi-res decode is in flight; selecting another file queues behind the running one (stale results discarded by name). A separate tiny channel preloads neighbor overviews into the LRU so Left/Right paging is instant. Loading is then progressive through that single slot: the overview (2048 edge) first, and a native-cap re-decode after the zoom crosses `NATIVE_ZOOM_THRESHOLD` that replaces the texture in place (same framing, no crossfade — see the Detail pump bullet). A cached overview shows the shader immediately (no thumbnail fade).
- **GPU exposure**: detail view runs through an `iced::widget::shader::Shader` that uploads the linear mono `Vec<f32>` once as an `R16Float` texture at decode time (single channel, f32→half converted in `Primitive::prepare` via `mono_to_half_bytes`; half-float is essential because `R32Float` is **not filterable** on WebGPU/wgpu 28 and would fail the `Float { filterable: true }` bind group validation). The WGSL shader applies `2^EV` in linear light and sRGB-encodes per fragment. `ExposureChanged(f32)` writes the new EV into a uniform via `shader.set_exposure(ev)` — zero CPU work, zero per-frame `Handle` allocation, no debounce (uniform writes are ~sub-millisecond). The math is bit-identical to the previous CPU sRGB-LUT path; the slider just moves a number now.
- **Editing panel**: when a detail view is active, the editing panel is shown in the COSMIC **context drawer** as a side pane (`core.window.context_is_overlay = false`, so the image shrinks to make room — matching the old inline 240 px panel). The drawer follows the detail view's **per-view remembered state** (`drawer_memory.detail` — see #18); the user brings the controls up with **Space** (the standard context-drawer toggle, per view) or the **View → Details…** menu item (disabled unless a detail view is open or a roll is selected on the library page; see #19) — there is no header toggle anymore (the old `edit-symbolic` button was removed; see the View bullet). Content: title, exposure slider (−3.00 to +4.00 EV, step 0.01, base +0.7 default); below that the **persisted** tone controls — Contrast, Highlight rolloff, and Shadows power sliders (all `0.20..=3.00` step 0.05 at 1.0 identity) — and no numeric value readouts (removed along with the per-section "Reset tone" button), then a divider and a **Reset all edits** button that restores every edit to the values the panel was opened with (the stored manifest state, persisted — see the Edit persistence bullet for the reset snapshot). While the GPU shader is loading the panel shows only the title. The drawer width comes from libcosmic's `context_width()` (344–480 px). (The full-screen preview feature — formerly bare `Space` — was removed in the Space-drawer swap; see #18. The Black/White output-level sliders from the follow-up were removed: the inversion already auto-anchors black per frame, so the only gestures available produced a fade rather than a fix.)
- **Zoom & pan**: the preview surface is wrapped in `DetailArea`; the wheel zooms (one notch ≈ half a `log2` unit) and press+drag pans. The maximum zoom is the **1:1 ("100%") cap** — one image pixel per one physical screen pixel — computed dynamically as `1 + log2(max(dw/sc_w, dh/sc_h))` from the loaded texture (cropped + rotation-swapped) and the preview area's physical size (`DetailProgram::zoom_100`; `DetailArea` reports its laid-out size via `on_resize` → `Message::DetailAreaResized`, `self.core().scale_factor()` converts to physical). `apply_detail_zoom` clamps to `[1.0, max_detail_zoom()]` (the cap, guarded by the `MAX_DETAIL_ZOOM = 7.0` absolute ceiling ≈ 64× contain); the cap is re-derived + re-clamped whenever it can change — preview resize, drawer open/close, the native level-up install (a larger texture WIDENS the cap), and crop/rotation edits (`reclamp_detail_zoom`). Zoom is **continuous from the contain fit**: `scale = contain_s · 2^(zoom−1)`, so at `zoom == 1` the view is byte-identical to today's `ContentFit::Contain` and bars recede gradually; the frame fills the shader at `1 + log2(cover/contain)` and keeps overflowing beyond (never clipped to the letterbox band — user's explicit requirement). The pan keeps the image point under the cursor pinned across zoom steps (`zoom_about_anchor`: `off1 = off0 + (1 − 2^(z1−z0))·(cursor − off0)`; the render scale is proportional to `2^(zoom−1)` so the unknown contain width cancels, and `DetailArea` supplies the cursor **center-relative** so the widget center never enters the formula either — iced's plain `MouseArea` gives top-left-relative positions, which would shift every anchor by the unknown widget center). Zooming back out to 1 re-centers (fit view must be centered); zooming out past cover does not snap. Pan is unclamped (bars show while dragging past an edge; a shader-side soft clamp is a possible later step). `on_release` also fires on cursor-leave-while-pressed and on `CursorLeft` so a grab-pan can never stick. Wheel zoom is gated on the cursor being over the `DetailArea` itself (the widget's `WheelScrolled` arm guards `if over`, like its press arm) — so scrolling the editing drawer, the caption/bars, or the header never zooms the image; the outer blocking `MouseArea`'s `on_scroll(Ignore)` (which iced's `MouseArea` also gates on cursor position) remains as backstop for the grid.
- **Tone model (persisted, orthogonal controls — exposure, contrast, highlight rolloff, shadows)**: the editing drawer carries a live tone preview with **Exposure** (`2^EV` gain — everything moves together) and three **pivoted powers** — **Contrast** `kc` (pivot at the image's measured **mid-gray** `m`: `C(p)=m^(1−kc)·p^kc`), **Highlight rolloff** `kr` (pivot at the measured **white point** `w` ≈ 98th %ile: `R(p)=w^(1−kr)·p^kr`), and **Shadows** `ks` (pivot at the measured **shadow anchor** `s` ≈ 10th %ile: `S(p)=s^(1−ks)·p^ks`). The pivot-at-an-image-anchor framing is the whole point: the previous panel's D-max/gamma were *mathematically* near-duplicates of exposure — at default gamma, D-max `T(p)=(2.4/d)^0.7·p` is literally a pure gain (≈ ±0.9 EV), and gamma's power was anchored at the display black/white, far outside the frame's actual tone band, so it read as brightness too. Three monotone powers still compose **exactly** into one power `ratio·p^exp` (`ratio = s^(1−ks)·w^(ks·(1−kr))·m^(ks·kr·(1−kc))`, `exp = kc·kr·ks`, `curve_remap` in `shader.rs`); the GPU consumes it through the 2048-entry tone LUT (`build_tone_lut`, see #14), the CPU bakes call `shader::tone_model` directly — at defaults `kc=kr=ks=1` the remap is the identity and untouched renders stay (sub-1e-6) identical. (Output-level **Blacks/Whites** endpoints were prototyped and **removed**: the inversion already auto-anchors black per frame via `film::positive` mapping `transmission == base` → exactly 0, so the only slider directions available raised the floor to grey or clipped highlights the rolloff power already shapes — a fade, not a fix.) Anchors are measured once per detail decode: for an already-positive preset with `tone_anchors` (single-pass 4096-bin histogram over the uploaded positive, O(n) — no sort of a 2048² buffer; 10th/50th/98th percentiles, all clamped to ≥ `MIN_ANCHOR`=1e-3 to keep `pow(0, negative)` from NaNing degenerate all-black frames); for an inverted (film) preset the sensor fractiles (`film_anchor_fractiles`, stride `ANCHOR_INV_STRIDE = 4`) are measured once and the pivots are derived at the CURRENT EV (`film_pivots_at_gain` — `set_exposure` re-derives on every slider tick, so the anchors always describe the actual render, EV-exact, closing the old detail-vs-bake anchor drift). `curve_remap` also floors the shadow pivot at `mid · SHADOW_PIVOT_FLOOR` (0.15) so a hard-black frame keeps a usable Shadows power. The tone edits are **persisted** like exposure: `clear_detail()` resets the powers to 1.0 but every open re-sources the stored `(contrast, rolloff, shadows)` from the manifest, and grid thumbnails bake them too. The shared pure helpers `curve_remap` / `tone_model` / `apply_curve` (all `pub(crate)` in `shader.rs`) keep grid, export, and detail agreeing: `convert_thumbnail` and `export_one` bake through the one `bake_tone` tail (measure → `apply_curve` → exposure → sRGB), and the detail shader samples the same tone model via the LUT — the only approximation, bounded by the #14 parity tests. Caveats accepted: the LUT re-rounds through the f16 texture and linear interpolation (gamma-domain packed toward black, ≤ ~1e-3 pre-exposure, so sub-visual); unsharp edge detail was computed pre-curve and is re-curved rather than re-derived.
- **Edit persistence**: each image's exposure and tone-curve power edits survive image switches, detail close, and app restarts via a per-roll manifest, `.film-roll.toml` (TOML, `{ version, name?, edits: { <name>: { exposure_ev, curve_contrast, curve_rolloff, curve_shadows, crop: { top, right, bottom, left } } } }`, schema `version = 7` — v7 adds roll-level `start_date: Option<String>` + `end_date: Option<String>` (ISO dates from the roll-info drawer), v6 added the roll-level `base: Option<f32>` (recorded calibration) + `base_auto: bool` (per-frame auto opt-in, default false; v5/v4/v3 load `None`/`false`) — ) the `crop` sub-struct (`CropMargins`, source-pixel margins per edge, `#[serde(default)]`) was added in v4 (v3 manifests load as a zero crop) and `rotation: u8` (cumulative CCW quarter-turns, `#[serde(default)]`) in v5 (v4/v3 load rotation 0). Crop and rotation are **not** part of `ToneEdit`, so copy/paste (`clipboard: Option<ToneEdit>`) inherently excludes them; both are read/written via dedicated `RollManifest::crop(name)`/`set_crop(name, ..)` and `rotation(name)`/`set_rotation(name, ..)` living in the roll directory (the POC's initial `~/Pictures/curvectrl` before the seed was removed). The manifest file name is deliberately function-based rather than app-based so an **app rename never orphans existing sidecars** (remember also `APP_ID = "io.github.jpttrssn.curvectrl"` and `CARGO_PKG_REPOSITORY` when renaming; `Config` follows `APP_ID` automatically). Loading: `RollOpened` loads the active roll's manifest once on drill-in and `reconcile()` drops entries whose file is no longer in the scan, so a recycled file name can never reattach stale edits. Writing is RAM-first: `ExposureChanged`/`CurveChanged` mutate `roll.edits` only; flushes happen on slider drag-end (`Slider::on_release(Message::EditSave)`), on `DetailClosed`, and on window close (`on_close_requested → None→Some(EditSave)`); `save_roll_manifest` writes a temp file then renames (atomic). Reads consolidate on `ToneEdit` — a `pub` aggregate of exposure + the three powers with an identity `Default` — via `RollManifest::tone(name)`; the granular getters (`exposure_ev`/`curve`) were dropped once the app read wholly through `tone()`. (The `level_blacks`/`level_whites` fields from the follow-up were removed along with the controls.) **Grid thumbnails reflect edits too**: `decode_next()` reads the full `roll.tone(name)` at spawn and `convert_thumbnail` bakes it all in — the curve powers through the shared `shader::apply_curve`, then `apply_exposure` (all identity at defaults) mirroring the shader's exact ordering, so grid == detail; `EditSave` additionally re-bakes the selected tile (back to `Thumb::Loading`, then pumps). **Roll tiles reflect their cover's edits the same way**: `decode_cover` reads the manifest's `tone(cover_name)`, and `EditSave` also re-bakes the library roll cover in lockstep when the edited frame is that roll's cover file — grid, detail, and the library card stay in agreement. Opening a file (`ThumbnailActivated`) persists outgoing edits, then reads the stored `ToneEdit` back into the four live values AFTER `clear_detail()` zeroes them and BEFORE `decode_detail_next()` builds the shader (which consumes them via `set_curve`). Saving is per-roll and directory-parameterized (`load_roll_manifest(dir)`, `save_roll_manifest(dir, …)`): each roll directory owns its `.film-roll.toml` sidecar, so multi-roll is structural — the manifest flushes on drill-out (`persist_roll()` on `RollActivated`/`DetailClosed`) and on window close. **Reset all edits** (`ResetAll`) restores those same values, not the identity: `ThumbnailActivated` snapshots the loaded `ToneEdit` into `reset_exposure_ev`/`reset_curve_contrast`/`reset_curve_rolloff`/`reset_curve_shadows`, and `ResetAll` writes the snapshot back to the live values + shader + `roll.edits` (flushed on the usual points), so reset reverts the panel to the state it was opened with — idempotent and anchored (a second reset returns to the same snapshot). `clear_detail()` resets the snapshot fields to identity alongside the live ones, so the next open re-syncs them. `clear_detail()` still resets `exposure_ev = 0.0` and curve to 1.0 — harmless, since every open re-sources from the manifest. Storage is parameterized by directory (`library_dir()`, `load_roll_manifest(dir)`, `save_roll_manifest(dir, …)`), ready for the planned multi-roll feature where the *user* owns file structure and each roll gets its own manifest. Known trade-off: renaming/moving a file *inside* a roll orphans its edit (the name is the key) — acceptable given user-owned structure; TOML keeps the file hand-editable.

- Decode chain: `decode_next()` fills up to `MAX_CONCURRENT_THUMBS` slots with distinct `Loading` tiles → one `tokio::task::spawn_blocking` per file (`decode_thumbnail`), returned as a `Task::batch`. Bounded concurrency keeps a handful of full-res RAW buffers alive at a time (each is released once it finishes downscaling) instead of one — several parallel decodes on multicore. `thumb_inflight` (a `Vec`) enforces the cap and de-duplicates: a name already running is never spawned again, so a re-bake requested mid-chain waits for its decode instead of racing it, and the EV + tone curve are read at spawn time — startup tiles bake stored edits, re-baked tiles bake the freshest. `ThumbReady` removes the finished name and pumps; `RollOpened` clears the set (fresh roll = fresh chain), the final `DetailClosed` roll-exit drops it, `RollsLoaded` clears it alongside a new roll round. Roll covers are pumped by the sibling `decode_covers()` — same cap/discipline, keyed by dir via `cover_inflight`; each cover bake reads the cover file's stored `tone(name)` from that roll's manifest (mirroring the frame path), so a roll tile reflects its edited cover.
- Detail pump: `decode_detail_next()` spawns only when no decode is in flight and something is selected. **Progressive two-level loading through the single slot**: with no shader yet it decodes the 2048 overview; once `detail_zoom ≥ NATIVE_ZOOM_THRESHOLD` the first wheel past 2× contain spawns a native-cap re-decode (`MAX_TEXTURE_EDGE` = 8192) whose arrival swaps the texture in place — `fresh_open` (shader absent) gates the thumbnail fade so a level-up never re-flashes the thumb, and the swap re-applies the current zoom/pan + tone curve so framing holds. `detail_native_queued` makes the level-up one-shot (`DetailZoom` trigger + the flag gate), and is set early when the sensor's true long edge (post-crop, pre-downscale — `src_long_edge`, threaded out of `decode_raw_detail`) never exceeded `HI_RES_SIZE` (≤ 2048 — nothing bigger exists). The native-ness decision must use that *source* edge, NOT the capped overview width: a large sensor downscaled to just under 2048 would otherwise be mistaken for a small one and the level-up permanently suppressed (the original `2047 < 2048` false-positive that broke 18MP files). A superseded decode's arrival frees the slot via the stale guard and re-pumps. **Landing-time re-pump**: a trigger fired into an *occupied* slot is silently swallowed, so if the user wheels past the threshold while the overview is still decoding, `handle_detail_ready` re-checks the trigger right after freeing the slot (on the `Ok` landing only — an error landing never spins the slot) and starts the native level for the now-loaded overview. Failures do NOT auto-retry (re-selecting the file retries on demand; after an `Err` landing the zoom trigger stays live, so the next wheel retries). **LRU + preload**: when an overview is requested (`detail_shader` absent), `decode_detail_next` first consults `detail_cache` — a hit builds the shader from the cached mono (`install_detail_shader`) and returns with no decode, no thumbnail fade (instant return); misses decode and `handle_detail_ready` inserts the fresh overview (native level-ups are never cached). `open_frame` also calls `preload_detail_neighbors`, which fills the LRU with the `DETAIL_PRELOAD_DISTANCE` frames either side of the current one in the filtered set (closest first, honoring the `MAX_CONCURRENT_PRELOADS` bound and skipping already-cached/in-flight frames); landings arrive via `DetailPreloaded` → cache insert only. Edits are applied in-shader at open time, so a cached mono stays valid across edit changes.
- Thumbnail pipeline (`convert_thumbnail(image, max_size)`): `rawloader::decode_file` → `downsample_thumbnail` (fused normalize + crop + phase-preserving block average straight from the sensor buffer: bayer classes rescaled onto one common base per `class_gains`, cpp≥3 via luma-of-channel-means) → `unsharp_mask` (true sensor space) → the one shared tone tail `bake_tone` (see #14) — for an inverted (film) preset the EV gain hits the true sensor data first (`2^-EV` — the `sensor_gain` flip, +EV brightens), then `film::invert_gray`, with the pivots derived EV-exact from the raw sensor fractiles just like the detail shader; an already-positive scan (`None`) gets histogram `tone_anchors` + curve, then the `2^EV` gain; both finish with `srgb_encode` → u8 quantize as `[v,v,v,255]` → `orient` → `Handle::from_rgba`. Grid == export == detail hold structurally because this single body (plus its GPU-LUT parity tests, see #14) is the only place the tone math lives for the non-shader paths; all identity at defaults.
- Detail pipeline (`decode_raw_detail`): same as the thumbnail pipeline through `unsharp_mask` on `Vec<f32>` mono, then `orient_mono` (per-element float mirror of `orient`) and returns a `DetailDecode { mono, width, height, src_long_edge, inversion }`. The mono is TRUE sensor-linear for every preset — no CPU inversion — and `inversion: Option<(MonoStock, f32)>` is `Some((stock, base))` for a film negative (the EV-0 clear-film anchor measured per frame) or `None` for an already-positive scan; `src_long_edge` is the sensor's true long edge after cropping, before the downscale, which `handle_detail_ready` uses to decide whether the overview was already native. The downscale cap is a parameter (`max_edge`): `HI_RES_SIZE` at the overview level, `MAX_TEXTURE_EDGE` at the native level-up; `resize_area` treats a cap ≥ both source edges as identity (`scale` clamps to 1.0), so ≤8K and small sensors decode at true full resolution — the small-scan overview simply marks the level-up done. The GPU shader does the per-fragment density inversion (film) + sRGB encoding.
- **GPU pipeline** (`Pipeline::new` in `src/shader.rs`): one-time creation of `ShaderModule` from `include_str!("shader/exposure.wgsl")`, `BindGroupLayout` (texture, sampler, uniform buffer), `PipelineLayout`, `RenderPipeline` (fullscreen triangle, target format `Bgra8Unorm` to match iced's framebuffer on this libcosmic configuration), `Buffer` for the `Uniforms` struct, and a `Sampler` (linear + ClampToEdge). The texture + bind group are created lazily in `Primitive::prepare` on the first frame because they need the mono data. Subsequent frames: only the uniform buffer is updated via `queue.write_buffer`. The WGSL `fs_main` already applies `linear_to_srgb` per fragment, so the target is `Unorm` (linear) rather than `UnormSrgb` — picking `UnormSrgb` would double-encode. The `_format` parameter iced passes is ignored; if libcosmic ever switches to an sRGB-aware framebuffer, this would need a paired change (drop `linear_to_srgb` from the shader or no-op it, then swap the target back to `Bgra8UnormSrgb`).
- WGSL uses the canonical 3-vertex fullscreen triangle (`-1,-1 / -1,3 / 3,-1`) with NDC values passed through directly. Earlier pattern `(vec2(1u, 2u) + vi) % vec2(6u) < vec2(3u)` produced only the upper-right half of the viewport (visually a triangle), because under wgpu the render-pass scissor clips to the viewport rect rather than to the original primitive's bounds.
- `Uniforms.exposure` carries the sensor-space gain, NOT the raw EV: `2^EV` for an already-positive preset, `2^-EV` for an inverted (film) preset (`sensor_gain(ev, inverted)` — the sign flip happens at the point EV meets the sensor data, so +EV always brightens the positive). `Primitive::prepare` computes the gain once per slider change via `sensor_gain`. At EV=0 the gain is exactly 1.0 (identity). Sending raw EV would render black at EV=0 and over-bright at EV≥1 because the shader's `mono_linear * exposure` would multiply by the slider value instead of the matching gain.
- Texture re-upload is keyed by `image_id: u64` so selecting a second image actually rebuilds the GPU texture and bind group. `AppModel.next_image_id` is a `wrapping_add(1)` counter stamped onto `DetailProgram::image_id` in `handle_detail_ready`; `DetailPipeline::current_image_id: Option<u64>` remembers the last installed id. Without this, iced reuses the same `DetailPipeline` across image selections (it caches by `TypeId`) and the previously-uploaded mono data stays bound to the new shader — visible as "second image still shows first".
- Detail view layout: the shader widget is `Length::Fill × Length::Fill` directly inside a Fill × Fill `widget::container` — no wrapping Grid. Because `widget::Shader` has no `.content_fit()` setter, the WGSL shader does `ContentFit::Contain` math itself (`contained_uv` in `exposure.wgsl`): compares `cell_aspect` against `tex_aspect` and remaps UV to the contained sub-rectangle. **Letterbox/pillarbox bars are alpha-blended (`vec4(0, 0, 0, 0)` + `BlendState::ALPHA_BLENDING`) so the COSMIC panel background shows through** rather than rendering solid black frames. Earlier approach with `Grid::with_capacity(1).height(Sizing::AspectRatio(1.0)).columns(1)` failed because the Grid reports widget bounds = `(available_width, available_width)` and iced_wgpu's `Primitive::render` uses `instance.bounds ∩ physical_bounds` for `set_viewport` — not the parent's clipped viewport — so when `available_width >` the column's available height the shader painted pixels in the header. The Fill × Fill path keeps the shader widget bounded at the parent column's allocation; no overflow.
- **Per-frame uniform** (80 bytes, `Uniforms` struct, matches WGSL): `exposure: f32` (= the `sensor_gain` gain, `2^EV`/`2^-EV` per preset), `tex_w, tex_h: f32` (texture dimensions for the WGSL contained math), the fragment-shader-readable scissor rect expressed in physical pixels (`sc_x, sc_y, sc_w, sc_h` — computed from `bounds.{x,y,width,height} × viewport.scale_factor()`), `zoom: f32` (log2 units, 1 = contain), `pan_x, pan_y: f32` (image-center displacement, **physical** pixels — `prepare()` multiplies the logical pan by `viewport.scale_factor()`), the crop box `crop_x, crop_y, crop_w, crop_h: f32` (source-pixel margins collapsed to a center/box used by `crop_uv_geometry` for the UV-remap), and the film-inversion block `inv, inv_base, inv_d_max, inv_gamma: f32` (`inv != 0` switches `shade()` into the density-inversion branch; `inv_base/d_max/gamma` mirror the stock's `MonoStock` per-frame values). The tone remap left the uniforms in the LUT rework (#14): the 2048×1 `R16Float` `t_tone` texture (bindings 3/4) carries the curve, re-uploaded by `prepare()` only when `tone_version` changes. The layout is 20 f32. The shader's `view_uv` replaces `contained_uv`: `scale = min(sc_w/tex_w, sc_h/tex_h) · 2^(zoom−1)`, then the centered box is displaced by pan; fragments outside the moved box output alpha 0 (same blend trick as the bars), so panning past an edge shows the panel background rather than clamped pixels.
- Constants: `THUMB_SIZE = 384.0` (decode cap + grid cell), `HI_RES_SIZE = 2048` (detail overview decode cap), `FADE_SPEED = 5.0` (thumb-fade-out units/second, ~0.2 s ramp), `TILE_ASPECT = 1.0`, `UNSHARP_AMOUNT = 0.4`, `BASE_SAMPLE_TARGET = 250_000`, `MAX_CONCURRENT_THUMBS = 4`, `DETAIL_CACHE_CAPACITY = 40` (LRU frames kept, ~a film roll), `MAX_CONCURRENT_PRELOADS = 2` (neighbor preload decode bound), `DETAIL_PRELOAD_DISTANCE = 1` (frames either side of the current one preloaded), `MAX_DETAIL_ZOOM = 7.0` (≈64× contain — absolute ceiling on the dynamic 1:1 cap, see the Zoom & pan bullet), `NATIVE_ZOOM_THRESHOLD = 2.0` (level-up trigger, log2 units), `MAX_TEXTURE_EDGE = 8192` (native level-up cap, wgpu's typical texture ceiling), `CROP_STEP_PX = 2` (bare-key trim), `CROP_NUDGE_PX = 1` (Shift nudge), `MIN_LEFT: u32 = 2` (aspect-lock min margin per axis).
- View: the page body is just the content view — the in-roll back-button controls row was removed, so Esc (via `DetailClosed`) is the way out of a roll; there is no library toolbar either. The COSMIC header `header_end` packs only the search control (the editing-toggle button was removed — the editing drawer follows the detail view's per-view remembered state and is raised by Space or the View → Details… menu; Space toggles the current view's context drawer, see #18), which mirrors cosmic-files' `header_end` exactly: when search is **inactive** (`search` is `None`) it shows a `system-search-symbolic` icon button (`.tooltip("Search")`, `on_press(SearchActivate)`, padding 8); clicking it (or Ctrl+F) activates and focuses the input, and while **active** the icon is replaced by a fixed-width (`Length::Fixed(240)`) `search_input` — `on_input(SearchInput)` / `.id(search_input_id())` / `on_clear(SearchClear)` — hiding back to the icon once cleared. The library body is `Grid::with_children(cells.iter().enumerate().map(...))` over the unified `library_cells(&app.rolls, app.search.as_deref().unwrap_or(""))` set — each cell rendered with its selection state (cell 0 is the add tile, later cells the filtered rolls) — with `.fluid(THUMB_SIZE)` + `.height(grid::Sizing::AspectRatio(TILE_ASPECT))` inside a scrollable that wraps the grid in `widget::container(grid).width(Length::Fill).padding(space_s)` — the 16px inset (this iced fork's `Scrollable` has no `.padding()` builder; the inner container supplies it). with an empty cell set on a no-match search (nav simply has no destination). The Add Roll tile exists only while the search is inactive: it leads the grid idle (cell 0: a `Container::Primary` card via the shared `selectable_tile` wrapper — same selection ring) with the "Add Roll" label above a `list-add-symbolic` icon — a `MouseArea` with `on_press(AddRollSelected)` + `on_double_click(AddRoll)` so single-click selects and double-click opens the folder picker; a non-empty search term hides it and File → Add roll stays available as the inline-picker alternative. Empty states: an empty library shows **no hint** (the add tile alone is self-explanatory; the old `no-rolls` message key was removed), while rolls-that-match-nothing-overlays the search-mismatch `no-rolls-found` hint over the space the grid leaves empty. Each card is one interactive unit: an outer `MouseArea` (`on_press(RollSelected)` + `on_double_click(RollActivated)`) wraps the whole card — a full-bleed cover, title, and the `roll-frames` caption (`text::caption`, localized plural "{count} frame(s)" from `Roll.frame_count`) — so single-click selects and double-click opens anywhere, even on a still-decoding cover. The cover is flush to the card's top edge with no padding and uses `content_fit(ContentFit::Cover)` + a **top-only** `border_radius(border::Radius::default().bottom(radius))`: iced-wgpu's image shader clips fragments to a rounded-box SDF, so the card's top corners genuinely cut into the photo while the cover's bottom corners stay square (interior edge). The bottom-call is deliberate — the pinned image shader applies its `vec4` radius rotated 180° from `border::Radius`'s struct order (first two entries render on the bottom), so the top clip is expressed via `.bottom()`. `radius` comes from `cosmic::theme::active().cosmic().corner_radii.radius_s[0]`, so the clip matches the COSMIC system Roundness setting (rounded/slightly-rounded/square) exactly as `Container::Primary` resolves it — nothing hardcoded. Landscape crops ~nothing; portrait center-crops top/bottom. Title + caption sit in an `info` container padded `space_xs` (12px) all round, whose top padding is also the cover→text gap (the card column uses `.spacing(0)`); cover placeholders (`image-loading/missing-symbolic`) stay centered in the same Fill×Fill sheet. **Selection is an overlay, not a card style**: the card sits in a `Stack` on a `Container::Primary` surface (radius from the theme), and a selected card gets a transparent `Container::custom` overlay ring on top — accent border 2.0 wide, radius `radius_s` — so the full-bleed cover can never hide the highlight (iced paints a container's border *behind* its children; the prior card-border highlight was exactly that, and the full-bleed image covered the top/left/right segments). The ring is decorative (no `MouseArea`), so it never eats the card's clicks. Cover fallbacks stay `image-loading/missing-symbolic`; the `no-rolls-found` (search-mismatch only) empty state and the `grid_cols` column math are unchanged, and the library selection/nav and the roll highlight now share the same `selectable_tile` + `selection_ring()` chrome over the unified `library_cells`, mirroring the same `Grid::fluid` layout. Drilled in, the body becomes the frame grid built by `cosmic::iced::widget::Grid::with_children(tiles.map(tile_view))` with `.fluid(THUMB_SIZE)` + `.height(grid::Sizing::AspectRatio(TILE_ASPECT))`, wrapped in `scrollable(container(grid).width(Fill).padding(space_s))` (the same 16px frame), filtered by the header search with a `no-files` empty state. Frame tiles are selectable like the library cards: a single `MouseArea` (`on_press(FrameSelected)` + `on_double_click(ThumbnailActivated)`) wraps the whole tile — `Contain` image (never cropped, so a film frame's full framing stays visible) over a `space_s`-padded name — on a `Container::Primary` surface, with the same shared `selection_ring()` overlay on a `Stack` when `frame_selected` matches. When a selection exists, `detail_view()` is pushed onto a `Stack` OVER the always-mounted grid (bottom: grid scrollable; top: detail in an opaque window-background container) instead of replacing it — the grid keeps its scroll state and stays interactively off-limits via a blocking `MouseArea`, while the preview surface itself is the interactive `DetailArea` (wheel zoom, grab-pan) nested inside the blocker: iced delivers to the inner widget first so its `capture_event()` wins for events over the preview, and the blocker's `Ignore` handlers remain effective over the caption/bars. The detail view fills the full content width; the editing panel is the COSMIC context drawer in side-pane mode. COSMIC left toggle (View menu) holds About + Details (`MenuAction::Details` bound to `Space` in `key_binds` — shared with the bare-Space drawer toggle — and gated on a detail view or a library roll selection, see #19).

## Known limitations (likely next-step targets)

1. **Tone editing is manual, not a stock**: the fixed inversion stock is `film::ACTIVE_STOCK` (HP5+). The editing drawer is a *persisted* manual contrast/rolloff/shadows control (see the Tone model + Edit persistence bullets), not yet a picker of real `MonoStock`s (each a tuned `(d_max, gamma)` preset that could drive the same `(ratio, exp)` uniforms). Cast WB stays self-calibrated per image from clear-film plateaus, so margin-less frames rely on the `MIN_PLAUSIBLE_BASE` fallback. **Calibrate-base-from-this-frame is implemented** (`measure_base` does the math; Edit → Calibrate base from this frame records a roll-level override — see #13), so the remaining natural next steps are AsShot-WB priors for margin-less frames and color stocks using `invert_mono`/`measure_base_channels`.
2. **No live refresh**: re-adding a roll re-scans it (the Add Roll tile doubles as a manual refresh), but an open roll's frame list is fixed for the session and the library list has no global rescan button.
3. **Memory unbounded** across many decoded thumbs (no LRU/eviction); ~600 KB each. Detail view holds one oriented mono `Vec<f32>` (~16 MB at 2048×2048 f32) + its GPU texture; zooming past the threshold re-decodes it at native cap (`MAX_TEXTURE_EDGE`), so a >8K sensor transiently holds up to a `long_edge ≤ 8192` mono buffer (~0.5 GB worst case at 8192² f32) until the old buffer is dropped on swap. Live buffers are dropped on close/reselect, but the **detail-overview LRU** (`DETAIL_CACHE_CAPACITY` = 40 × ~12–17 MB ≈ 500–670 MB peak) deliberately retains recently-viewed overviews across close/roll switches — a bounded, intended tradeoff for instant return; native level-up buffers and the thumbnail no-cache policy are unchanged.
4. Decode errors are silent (`Err(())`); non-RAW files are listed and show the missing icon. A failed hi-res detail decode likewise keeps showing the thumbnail — selecting another file and back retries on demand.
5. **Grain/noise/sharpness**: area-average downscale, luminance collapse, full-res bayer flattening, gentle unsharp mask — plus the post-decode bandwidth savings on the GPU side (one linear texture upload vs. a continuously-re-encoded sRGB image). Remaining stackable option — a denoise pass for very underexposed captures. Capture-side: scans exposed with clear film far left in the histogram waste SNR; exposing so the base sits near saturation (~85–95%) keeps several more stops of detail in dense areas.
6. **Exposure EV precision**: the exposure edit is stored in the manifest and pushed to the GPU uniform as `f32` (`Uniforms.exposure`, `EditData.exposure_ev`), but the slider only spans −3..+3 EV at 0.01 steps (~600 discrete values). Revisit whether the accuracy/width is justified — e.g. a fixed-point or narrower type in the manifest, or whether the shader could take the EV precomputed as f16 via `R16Float`-style storage rather than f32.
7. **GPU vs CPU for thumbnails (decided: CPU)** — evaluated when wiring edit-aware tiles. GPU does NOT help thumbnail *loading*: `rawloader::decode_file` is the dominant cost and is CPU-only; the quality-relevant steps (full-res `flatten_bayer`, linear-light area-average downscale) are intentionally CPU-side because a GPU sampler can't do area-average (mip/bilinear differs), and uploading full-res mono per tile would be ~100 MB/tile. The GPU-able tail (EV multiply + sRGB + quantize at ≤384 px) is trivial CPU, so per-tile shader objects buy nothing. GPU stays where it already pays: the single live detail shader. Consequence taken instead: thumbnails are *re-decoded* CPU-side with the EV baked in on edit release — one RAW re-decode per edited file, background + bounded-concurrent, so the grid updates a beat after the detail view. If instantaneous grid feedback were ever required, the alternative is caching the un-exposed linear mono per tile (~590 KB @ 384 px f32) and re-encoding on edit — rejected now because it breaks the memory-boundedness that the concurrency cap/no-cache currently guarantees (see #3). The accepted flatten-before-average tone swap (per-class bases measured at thumbnail scale after averaging) plus the ≤4-way decode concurrency (transient RAM peak ≈ `MAX_CONCURRENT_THUMBS` decoded full-res buffers) are the current price of the speedup; `CONCURRENT_THUMBS` is a one-line knob.

15. **Export (File → Export… / bare `e`)** — **implemented**. Exports the current selection (every multi-selected frame, else the focused frame; no-op + disabled menu item without a target) into a folder chosen in the **native open-folder dialog** (`cosmic::dialog::file_chooser::open::Dialog::open_folder()`, the same dialog Add Roll uses; xdg portal, app builds with `xdg-portal`). One file per frame named `<stem>.<ext>` (source extension replaced), overwriting in place. Two **portal choices** render in the dialog: a **format dropdown** (`export_format_choice()` → `Choice::new("format", ..., "jpeg-90").insert(...)`, keys `jpeg-90`/`jpeg-82`/`png-16`): **JPEG 90% full-res**, **JPEG 82% 2048**, **16-bit PNG full-res**; and an **overwrite checkbox** (`export_overwrite_choice()` → `Choice::boolean("overwrite", ..., false)`, **default "no"**). The response's `choices()` `(id, value)` list is resolved by the pure `options_for_choice(&str) -> ExportOptions` (unknown key / a backend that dropped the choice → first preset) plus the overwrite state (`id == "overwrite"`, value `"true"`). **Wiring**: `MenuAction::Export` → File-menu item, bare-`e` key_bind, `Message::ExportRequested` guarded by `has_export_targets()` + `export_pending` (the portal dialog is modal and blocks window input, but the flag prevents a double-fire in the async gap before it appears) spawns a `cosmic::task::future` that awaits the dialog and routes `Message::ExportChosen(Option<(PathBuf, ExportOptions)>)` — `Some` → `begin_export(dest, options)`, `None` (cancel) → no-op. `begin_export` snapshots edits from the **in-memory** `self.roll` manifest — the same RAM source the grid and detail view render from, no on-disk re-read — so an export always matches what is on screen even for an edit applied but not yet flushed, then `export_frames(..., options)` → `export_one` runs on the blocking pool **sequentially**; `export_frames` returns `(ok, skipped, failed)` and, with overwrite off, skips any frame whose `<stem>.<ext>` already exists **before decoding**. `export_one`: `decode_raw_detail(dir, name, max_edge)` keeps its `(mono, w, h, src_long_edge)` tuple; `max_edge` = size's `long_edge()` (0 → `u32::MAX`, native); downscale factor = `max_edge / src_long_edge` pins crop margins onto the print via `scale_crop(crop, source_w, source_h, w, h)`; bake order = `tone_anchors`+`apply_curve` → `apply_exposure` → sRGB → geometry (**crop-then-rotate**, matching `convert_thumbnail`). Geometry is generic: `bake_geometry` (u8) / `bake_geometry16` (u16) wrap `crop_rgba`/`rotate_quarters` (and 16-bit twins `crop_rgba16`/`rotate_quarters16`) — the u8 wrappers are unchanged for the thumbnail/cover paths. **JPEG**: `export_jpeg` (mono → RGBA → single luminance channel, `jpeg-encoder` q from options + `ColorType::Luma`, dims `u16::try_from`). **PNG**: `export_png` writes lossless **16-bit grayscale** via the **`png` crate directly** (`png::Encoder` Grayscale/16, plus `set_pixel_dims` for a `pHYs` chunk) — the mono is baked through `bake_geometry16`, then only the luminance channel is kept (`px[0].to_be_bytes()`). Samples are emitted **big-endian** — the byte order the PNG container requires; the raw `png` crate writes them as-is (the previous `image::save_buffer_with_format` wrapper re-swapped native→big-endian itself, so that path needed `to_ne_bytes()`; bypassing it to set density means we now own the swap, `to_be_bytes()`). Both encoders are plain `fn` taking owned `mono: Vec<f32>` (dropped before the encode buffer, satisfying clippy's `drop_ref`). **Atomic writes**: every file is encoded to a same-directory `<name>.<ext>.tmp` sibling (`temp_export_path`) and renamed over the target only once the stream is fully written — `fs::rename` on the same filesystem is atomic, so a mid-encode failure cleans up the `.tmp` and never truncates (or, with overwrite on, replaces) an existing file; `ExportOptions` no longer stores the seeding `preset` (behavior is driven by `format`/`quality`/`size`/`ppi`/`overwrite` alone, resolved straight to options in `options_for_choice`). **Density metadata** (`ExportOptions.ppi: u16`, 0 = none): JPEGs tag JFIF dots-per-inch via `encoder.set_density(PixelDensity::dpi(ppi))` (the default header is a bare (1,1) pixel-aspect-ratio); the master PNG tags a `pHYs` chunk in **pixels per meter** (`ppm = round(ppi / 0.0254)` — 72→2835, 300→11811, `Unit::Meter`). Presets: **Cloud JPEG q90 full-res = 300 dpi** (print), **Web JPEG q82 2048 = 72 dpi** (screen), **Master 16-bit PNG = 300 dpi** (print floor). Pure header metadata — pixel data is untouched. **Grayscale rationale / color-negative note**: negatives render monochrome today (every channel is the same level), so all three export variants write a single channel — 16-bit grayscale PNG and Luma JPEG — which also cuts the master to ~1/3 of an RGB16 file. The geometry helpers (`bake_geometry`/`bake_geometry16`, crop-then-rotate) are already color-agnostic RGBA; when color negatives are eventually supported the export encoders must restore the RGB/RGBA interleave (`png::ColorType::Rgb16`, `ColorType::Rgb` for JPEG, plus a re-added 8-bit PNG option if desired) and stop discarding channels 2–4. `ExportDone { ok, skipped, failed, dest }` pops a `toaster` completion toast (`export-done`, or `export-done-skipped` when some frames were kept, or `export-failed`). **New dependency**: `image = { version = "0.25", default-features = false, features = ["png"] }` (the tree already pulled image 0.25.10 for decode, so no new crates enter the lock). Tests: `export_name_replaces_the_source_extension` (jpg + png + dotfile), `export_presets_define_the_expected_defaults` (Cloud q90 native, Master 16-bit PNG native, Web q82 2048, all overwrite=false), `options_for_choice_resolves_the_dropdown_keys`, `png_export_writes_grayscale_16bit_round_trip` (temp file, decodes the PNG and asserts grayscale 16-bit + the 0.5→32768 sample, pinning byte order, and a `pHYs` 2835 px/m chunk for the 72 dpi request), `jpeg_export_tags_the_jfif_density` (full `export_jpeg` at Web's 72 dpi, asserts the JFIF APP0 bytes), plus `jpeg_encoder_smoke_writes_quality_90_soi` (grayscale `Luma` encode). Hand-verify with `just run`: select frames → `e` → open-folder dialog (format dropdown + overwrite checkbox) → pick a folder → Export here; confirm Cloud JPEGs match the edited detail view (300 dpi), the 16-bit PNG is lossless and **no longer gray noise** (and lands ~1/3 of the old RGB size) tagged 300 dpi, Web JPEGs land at a 2048px long edge tagged 72 dpi (check with `identify -verbose` or GIMP), and re-exporting with the checkbox unchecked skips existing files (toast mentions the count). **First-principles round**: the PNG master also tags a `sRGB` chunk (`set_source_srgb(SrgbRenderingIntent::Perceptual)` — samples are sRGB-encoded, so color-managed print paths interpret them deterministically); and the roll scan (`load_files_in`/`roll_cover_and_count`) skips `.jpg`/`.jpeg`/`.png` files (`is_export_artifact`), so exporting a roll into its own folder never shows the shipped files back up as fake frames — or as the roll cover, which is scanned for negatives only. Unit tests pin these (`png_export_writes_grayscale_16bit_round_trip` now also asserts the `sRGB` chunk; new `export_artifacts_are_identified_by_extension`). **Progress indicator (header ring)**: `begin_export` streams per-frame ticks (`Message::ExportProgress { done, total }`) over `cosmic::task::stream(cosmic::iced::stream::channel(1, …))` — each finished frame `try_send`s a tick (droppable harmlessly under backpressure) and the final `ExportDone` is awaited *through* the channel so it always lands — into `AppModel.export_progress: Option<(usize, usize)>`. While a batch runs, `header_end` (right side of the header, after the search control) packs a small 18 px **determinate circular ring** (`cosmic::widget::determinate_circular(export_fraction(done, total)).size(18.0)`) with a hover tooltip showing `Exporting {$done} of {$total}` — COSMIC-Files-style, occupying **zero** screen space when idle. 25. **EXIF capture-time stamping on export (DateTimeOriginal + DateTimeDigitized)** — **implemented**. When the active roll carries a start date, every exported frame is stamped with two EXIF tags: **DateTimeOriginal** = `start date @ 00:00:00 + the frame's full-roll position in seconds` (a synthetic film-capture time, so cloud/photo apps sort exports chronologically even when they ignore filenames) and **DateTimeDigitized** = the RAW's own `DateTimeOriginal` (the scan/digitize time) when the file carries one. Rolls without a start date export un-stamped (unchanged behavior). **Implementation** — `src/exif_writer.rs` hand-rolls the small little-endian TIFF blob (`build_tiff`: 8-byte TIFF header → IFD0 with a single `ExifIFDPointer` entry → Exif IFD with the ASCII tags → fixed 20-byte NUL-terminated `YYYY:MM:DD HH:MM:SS` values) and the datestamp math (`shifted_datetime`: ISO date + seconds-from-midnight with day/month/year carry, leap-aware). JPEG output is encoded to a `Vec<u8>` and the blob spliced in as an APP1 (Exif) segment right after the SOI byte-order marker (`jpeg_app1`/`splice_after_soi`; the APP1 length field counts the 2 length bytes themselves, so `8 + tiff.len()`); PNG output gets the same raw TIFF via `Writer::write_chunk(png::chunk::eXIf, …)` after `write_header`, before the IDAT — `eXIf` omits JPEG's `Exif\0\0` prefix. **Indexing**: each frame's seconds offset is its **full-roll position** (index in the sorted `self.tiles` list = the grid/export order), captured in `begin_export`'s per-frame snapshot, so single-frame/subset exports get their absolute timestamp and re-exports are idempotent. `export_one` derives the blob (`start_date` + `index`, plus the RAW's own scan time read as its raw EXIF text via `exif_writer::raw_datetime_original` — **not** `load_frame_meta`'s display value, which kamadak normalizes to the hyphen `YYYY-MM-DD HH:MM:SS` form; `build_tiff`/`is_exif_datetime` enforce the exact `YYYY:MM:DD HH:MM:SS` colon shape and reject anything else) and passes it to the encoders. **No new crates** — kamadak-exif/jpeg-encoder/png are already in the lock; kamadak stays read-only and is used by the round-trip tests (note its crate name is `exif`, not `kamadak_exif`). Unit tests cover the date math (zero/end-of-day/day+month+year rollover, leap vs non-leap, malformed/unpadded rejection), the TIFF round-trip (read back via kamadak, incl. the Digitized tag), the JPEG splice end-to-end, hyphen-form rejection, and the raw `DateTimeOriginal` read-back round-trip. No mtime changes (per decision). Gates: **222 tests** (202 + 20 new), 8 baseline clippy warnings. Windowed check pending: export a dated roll (JPEG + PNG) and confirm via `exiftool` that DateTimeOriginal = start+i and DateTimeDigitized = the RAW's scan time.

## Useful API facts (verified against pinned libcosmic/rawloader)

- `cosmic::Task<M>` aliases `iced::Task<cosmic::Action<M>>`; async work: `cosmic::task::future(async { Message::X(...) })`; batch with `Task::batch([...])`.
- `rawloader::{RawImage, RawImageData, Orientation}` are re-exported at crate root (`decoders` module is private).
- `RawImage` fields used here: `width`, `height`, `cpp`, `data`, `wb_coeffs` ([f32;4] RGBE), `blacklevels`/`whitelevels` ([u16;4]), `orientation`, `cfa`.
- `rawloader::CFA` is crate-exported; `CFA::new("RGGB")` builds test patterns; `color_at(row, col)` mods internally (`(row+48)%48`), so any coordinates are safe. Returns 0=R, 1=G, 2=B, 3=fourth-color. `shift(x, y)` re-phases the pattern after cropping by `(left=x, top=y)`.
- `RawImage.crops: [usize;4]` is `[top, right, bottom, left]`. Tested Canon CR2s flag top/left only; their LAST two sensor rows also read elevated (~9k vs ~2k ADU) despite `bottom=0` — if a bottom-edge artifact ever appears, suspect unflagged masked rows.
- Icons: `icon::from_name("...").icon().into()` yields an Element; image handles clone cheaply. `widget::icon::from_name(...)` returns a `Named` with `From<Named> for icon::Handle`, so `.leading_icon(widget::icon::from_name(...))` works on buttons.
- **Roll library widgets** (verified against pinned libcosmic): `cosmic::dialog::file_chooser::open::Dialog::new().open_folder()` is async (xdg portal via ashpd), returns `FileResponse` whose `url()` is a `&Url` (path via `to_file_path()`); `Error::Cancelled` covers cancel/portal failure. No public dialog title setter exists in the pinned libcosmic, so the picker is invoked title-less. `widget::search_input(placeholder, value)` (`widget/text_input/input.rs:91`) returns a `TextInput` with `.on_input(Message)` and its own `system-search-symbolic` leading icon; `cosmic::widget::text_input::focus(Id)` reveals and focuses the input once it is mounted. `cosmic::Application` must be `use`d for `Self::APP_ID`/`core_mut()` inside plain `impl AppModel` blocks.
- **iced `widget::shader`** (verified against pinned vendored iced): reach through `cosmic::iced::widget::shader::{Pipeline, Primitive, Program, Shader, Viewport}`. `Shader::new(program).width(Length::Fill).height(Length::Fill)` wraps a `Program` impl. `Program::draw()` produces a `Primitive`; `Pipeline::new()` is called once when iced first sees a new pipeline type; `Primitive::prepare()` runs every frame; `Primitive::render()` runs every frame and uses an `encoder.begin_render_pass(...)` with `LoadOp::Load` (we draw into an already-painted framebuffer). `viewport.physical_{width,height}()` and `bounds.{x,y,width,height} × viewport.scale_factor()` give physical-pixel coordinates for the scissor region.
- **Other iced widget traits** verified for this feature: `MouseArea::new(content).on_double_click(message)` (takes a message value, not a closure); `cosmic::iced::keyboard::listen()` delivers only keyboard events widgets did NOT capture (Status::Ignored) — fine for a global Escape; `Subscription::filter_map` requires NON-CAPTURING closures (`Fn(T) -> Option<A> + Clone`); `cosmic::iced::widget::Stack::with_children([...])` layers children bottom-to-top in push order — used here for thumb-over-shader layering. `Rectangle::center()` (iced/core `rectangle.rs`) and `Cursor::position_in(bounds)` (cursor.rs) power `DetailArea`'s center-relative reporting; `ScrollDelta::{Lines, Pixels}` (iced/core `mouse/event.rs`) is what `on_scroll` receives — a wheel notch gives `Lines { y: ±1 }`, trackpads give `Pixels`.
- **Pure testable helpers**: the zoom/pan messages route through `apply_detail_zoom(zoom, pan, cursor, delta)` and `zoom_about_anchor(z0, z1, pan, cursor)` — no app state, so the pinned-point/round-trip/re-center invariants are unit-tested (`app.rs` tests). `detail_zoom_delta` maps `ScrollDelta → log2` units. The tone model is likewise pure: `curve_remap(contrast, rolloff, shadows, shadow, mid, white)` composes the three pivoted powers into `(ratio, exp)` and `tone_anchors(mono)` measures the 10th/50th/98th-percentile anchors from a histogram — unit-tested for identity-at-defaults, per-control pivot-pinning (`T(mid)=mid`, `T(white)=white`, `T(shadow)=shadow` at identity-others), exact three-power composition (single final clamp, matching the shader), and the degenerate-black guard (`MIN_ANCHOR`). The WGSL itself is validated in `shader::tests::wgsl_source_parses_and_validates` via a `naga` dev-dependency (already in the lockfile through wgpu, so nothing new compiles) — the shader is compiled by wgpu only at first launch, so a parse regression would otherwise surface only at runtime.
- **WGSL shader** (verified with vendored wgpu 28): `vertex_index` builtin provides 0..2; the per-vertex fullscreen-triangle pattern `vec2<f32>((vec2(1u, 2u) + vertex_index) % vec2(6u) < vec2(3u))` is the standard 3-vertex covering-trick; the render pass viewport is set to the primitive's bounds via `pass.set_viewport(...)` so NDC [-1..1] maps to the rect.
